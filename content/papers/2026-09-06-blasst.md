## 研究问题

长上下文注意力的两次主要矩阵乘法为：

$$
S=\frac{QK^\top}{\sqrt d},\qquad
P=\operatorname{softmax}(S),\qquad
O=PV.
$$

FlashAttention 通过 Tiling（分块）、Kernel Fusion（算子融合）和 Online Softmax（在线 Softmax）避免把完整的 $S,P\in\mathbb R^{L\times L}$ 写入 High Bandwidth Memory（高带宽显存，HBM），但仍然计算全部 Query-Key 交互，计算复杂度仍为 $O(L^2d)$。已有 Sparse Attention（稀疏注意力）通常先计算 Proxy Score（代理分数）、排序或物化稀疏索引；路由开销可能抵消理论收益，而且很多方法只支持 Prefill 或 Decode，需要重训，或者难以接入现有 Attention API。

BLASST 要解决的是一个部署问题：能否不增加独立路由阶段，直接复用 FlashAttention 已经必须维护的统计量，在现有 Kernel 内动态识别 Softmax 后几乎为零的 Block，并同时覆盖 Prefill、Decode、Multi-Head Attention（多头注意力，MHA）、Grouped-Query Attention（分组查询注意力，GQA）、Multi-Query Attention（多查询注意力，MQA）和 Multi-Head Latent Attention（多头潜在注意力，MLA）。

## 核心方法

### 1. 用 Online Softmax 的最大值做 Late Pruning

将 Query 和 Key-Value 沿 Token 维分块。对 Query Block $Q_i$ 和第 $j$ 个 Key Block $K_j$，先照常计算完整分数：

$$
S_{ij}=\frac{Q_iK_j^\top}{\sqrt d}.
$$

对每个 Query Row，令当前 Block 的局部最大值和遍历至今的运行最大值分别为：

$$
\widetilde m_i^{(j)}=\operatorname{rowmax}(S_{ij}),\qquad
m_i^{(j)}=\max\left(m_i^{(j-1)},\widetilde m_i^{(j)}\right).
$$

标准 FlashAttention 随后计算：

$$
\widetilde P_{ij}=\exp\left(S_{ij}-m_i^{(j)}\right),
$$

并用它更新 Softmax 分母 $l_i$ 和输出累加值 $O_i$。BLASST 在指数运算之前增加判定：

$$
\widetilde m_i^{(j)}-m_i^{(j)}<\ln\lambda,
$$

等价于：

$$
\exp\left(\widetilde m_i^{(j)}-m_i^{(j)}\right)<\lambda.
$$

$\lambda\in(0,1)$ 是阈值。若判定成立，当前 Block 的所有未归一化 Softmax 权重都小于当前最大项的 $\lambda$ 倍，于是跳过：

- CUDA Core 上的指数、Row Sum 和 Softmax 缩放；
- Tensor Core 上的第二次矩阵乘 $\widetilde P_{ij}V_j$，即 BMM2；
- Decode Kernel 中对应 Value Block $V_j$ 的 HBM 读取。

实际 Kernel 先由每个线程判断自己负责的 Row，再用 Warp `VOTE` 和 Shared-memory Atomic 汇总；只有整个物理 Tile 可以安全跳过时才跳过。这个判定是单边保守的：若当前 Block 产生了新的最大值，则差值为 $0$，一定保留；未来出现更大值，只会使已经跳过的 Block 更不重要。早期尚未见到全局最大值时，少量不重要 Block 可能被多保留，只损失稀疏度而不会增加误删。

### 2. 长度感知的 Threshold Calibration

固定 $\lambda$ 在不同 Context Length（上下文长度）下会产生完全不同的稀疏度。论文观察到目标稀疏度相同时，最佳阈值近似满足：

$$
\lambda=\frac{a}{L},
$$

其中 $L$ 是 Context Length，$a$ 是由模型和目标稀疏度决定的 Scale Factor（尺度因子）。校准时，在同一次 Forward 中统计多组候选阈值的实际稀疏度 $s$，拟合：

$$
\lambda L=\alpha\exp(\beta s).
$$

部署时，用户只指定目标稀疏度 $S$：

$$
\lambda(S,L)=\frac{\alpha\exp(\beta S)}{L}.
$$

这把难解释的 Raw Threshold（原始阈值）转换为可操作的 Target Sparsity（目标稀疏度）。从累计误差角度也容易理解 $1/L$：若单个被删 Token 的相对权重上界约为 $\lambda$，候选 Token 数随 $L$ 增长，则让 $\lambda$ 按 $1/L$ 缩小有助于约束总删除质量；但 BLASST 并未给出与任务无关的严格输出误差保证。

### 3. Prefill 与 Decode 分别优化不同瓶颈

- **Prefill 通常 Compute-bound。** Kernel 跳过 Softmax 与 BMM2，但仍预取 $V$，因为带条件的 Value Load 会破坏规则流水线，而 HBM 此时不是主要瓶颈。
- **普通 Decode 通常 Memory-bound。** Kernel 必须读取 $K$ 并计算 BMM1 才能判断是否跳过，但只为保留的 Block 读取 $V$。作者先批量执行多个 $QK^\top$，得到一组判定后再批量发起必要的 $V$ Load，以避免条件依赖造成 Pipeline Bubble（流水线气泡）。
- **MLA Decode 可能重新变成 Compute-bound。** 此时除 Value Load 外，也跳过 Softmax 和 BMM2。

### 4. 可选的 Sparsity-aware Training

BLASST 默认是 Training-free（免训练）的推理优化。论文也实验了在 Fine-tuning Forward 中启用同一个稀疏 Kernel；被跳过 Block 在 Backward 中自然没有梯度，不需要新结构或辅助损失。模型因而学习把重要信息集中到能通过阈值的 Block，在 $50\%$ 到 $75\%$ 稀疏区间改善 Accuracy-Sparsity Trade-off（精度-稀疏度权衡）。

## 关键发现

- 在 Blackwell B200 上，约 $49.2\%$ 稀疏时 Prefill 为 $1.33\times$、约 $46.7\%$ 稀疏时 Decode 为 $1.25\times$；约 $71.9\%$ Prefill 稀疏时达到 $1.52\times$，约 $73.2\%$ Decode 稀疏时达到 $1.48\times$。
- Hopper H200 Prefill 在 $71.0\%$ 稀疏时同样达到 $1.52\times$；极高稀疏度下 Kernel 约为 $1.7$ 到 $1.8\times$，与不能跳过 BMM1 的结构上限一致。
- 约 $50\%$ 目标稀疏度下，Llama-3.1-8B 和 Qwen3-8B 在 RULER、LongBench、MATH500、AIME 2024、GPQA 和 LiveCodeBench 上基本保持 Dense Accuracy；论文中的少量提升可能来自去噪，也可能落在 Sampling 与评测波动范围内，不应解释为稀疏必然提高能力。
- 固定 $\lambda=10^{-3}$ 时，目标 $50\%$ 的实际稀疏度从 4K Context 的 $23.09\%$ 漂移到 64K 的 $74.63\%$；使用 $\lambda=a/L$ 后，同组长度的实际稀疏度约为 $46.96\%$ 到 $54.20\%$，平均目标误差约 $1.2\%$。
- Kernel Microbenchmark（微基准）不等于完整服务收益。Qwen3-30B-A3B、平均输入约 10K、平均输出约 6、并发 64 的 TensorRT-LLM 测试中，Time to First Token（首 Token 延迟，TTFT）和 Time per Output Token（每输出 Token 延迟，TPOT）提升约为 $1.1\times$。

## 我的提问

### Q1：BLASST 为什么必须先算完整 $QK^\top$，还能获得加速？

它用当前 Exact Score（精确分数）的 Block Max 与 Running Max 做判定，因此 BMM1 是路由信号本身，不能跳过。收益来自避免后续 Softmax、BMM2，以及 Decode 中约一半注意力 HBM 流量中的 $V$ 读取。也因此它没有把渐近复杂度从 $O(L^2)$ 改成次二次，Kernel 加速上限约为 $1.8\times$；真正价值是判断开销几乎为零、无 Proxy Recall 风险、容易替换现有 Attention Backend。

### Q2：它和我们的 Sol-Attn 最本质的区别是什么？

一句话：**BLASST 是 Exact-score Late Pruning；Sol-Attn 是 Proxy-score Early Routing 加 Tail Correction。**

BLASST 的路径是：

$$
\text{Dense Exact }QK^\top
\rightarrow
\text{Max-vs.-Running-Max Threshold}
\rightarrow
\begin{cases}
\text{Softmax}+PV,&\text{Keep},\\
0,&\text{Drop}.
\end{cases}
$$

Sol-Attn 把每个物理 Block 的 Key 和 Value 压成：

$$
\overline K_j=\frac{1}{B}\sum_{u=1}^{B}K_{j,u},\qquad
\widehat V_j=\sum_{u=1}^{B}V_{j,u},
$$

并用 Block Proxy Score：

$$
\widehat s_{ij}=\overline Q_i\overline K_j^\top
$$

进行路由。对第 $i$ 个 Query Block，根据其 Proxy Row 的均值 $\mu_i$ 和标准差 $\sigma_i$ 得到自适应阈值：

$$
\tau_i=\mu_i+\gamma\sigma_i,\qquad
\mathcal S_i=\left\{j:\widehat s_{ij}>\tau_i\right\}.
$$

这里用 $\gamma$ 表示 Sol-Attn 的统一 Standardized Cutoff（标准化截断），避免与 BLASST Calibration 中的拟合系数 $\beta$ 混淆。若 Proxy Logit 近似 Gaussian（高斯分布），平均 Exact Density（精确计算密度）近似为：

$$
\rho(\gamma)\approx1-\Phi(\gamma),
$$

$\Phi$ 是标准高斯累积分布函数。Sol-Attn 的外层循环实际计算：

$$
\widetilde S_i^{(t)}=Q_i\left(\overline K^{(t)}\right)^\top,
$$

其 Column Mean（列均值）正好是 $\widehat s_{ij}$。选中 Block 再进入内层循环计算完整 $Q_iK_j^\top$；未选中 Block 不直接清零，而保留零阶近似：

$$
D_{ij}^{\mathrm{approx}}
=B\exp\left(Q_i\overline K_j^\top\right),
$$

$$
N_{ij}^{\mathrm{approx}}
=\exp\left(Q_i\overline K_j^\top\right)\widehat V_j.
$$

所以两者的核心 Trade-off 是：

| 比较维度 | BLASST | Sol-Attn |
| --- | --- | --- |
| 路由时间点 | 完整 BMM1 之后 | 完整 BMM1 之前 |
| 路由信号 | Exact Block Max | Pooled $Q/K$ Proxy |
| 是否跳过 Exact $QK^\top$ | 否 | 是，只计算选中 Block |
| 未选中 Block | 直接丢弃 | Pooled-$K$/Summed-$V$ 近似 |
| Threshold | 相对 Running Max 的 $\lambda$ | Query-dependent $\mu_i+\gamma\sigma_i$ |
| 部署控制 | 需模型与长度校准 | 近高斯假设下一个 $\gamma$ 控制平均密度 |
| 主要误差 | 累计 Dropped Mass | Proxy 漏选与 Block 内异质性 |
| 当前范围 | Causal LLM Prefill/Decode | Bidirectional Visual DiT Forward |

粗略忽略常数，设 Sol-Attn 的 Exact Block Density 为 $\rho$、Block Size 为 $B$：

$$
C_{QK}^{\mathrm{BLASST}}\approx L^2d,
$$

$$
C_{QK}^{\mathrm{Sol}}
\approx\left(\rho+\frac{1}{B}\right)L^2d.
$$

因此 Sol-Attn 可以突破 BLASST 约 $1.8\times$ 的上限；论文在 128K Token、$90\%$ 稀疏时报告 $5.41\times$ Kernel Speedup。代价是额外维护 Pooled $K$、Summed $V$、Query-dependent Threshold，并依赖 Proxy 对重要 Block 的召回。

### Q3：两者谁的判断更“安全”？

BLASST 使用 Exact Logit，并且相对 Running Max 做保守判定，较少出现重要 Block 被 Proxy 漏选的问题；但它把被判定为小的贡献全部清零，多个小贡献累积后仍可能显著。Sol-Attn 的 Proxy 可能漏掉“平均值低、内部存在少数大 Logit”的异质 Block，但 Exact-or-Approx 路径会保留其低阶贡献。Sol-Attn Appendix 的误差分析表明，近似分母误差对 Block 内 Centered Score Spread（中心化分数离散度）为二阶，分子误差还取决于分数偏差与 $V$ 的对齐。

## 局限与疑问

- BLASST 不能跳过 BMM1，仍是 $O(L^2)$，不减少 KV Cache 容量，只减少后续计算和部分读取带宽。
- 单个 Block 的最大权重小，不代表所有被删 Block 的累计 Probability Mass（概率质量）一定小；$\lambda\propto1/L$ 是有效经验规律，但不是逐 Row 的严格误差预算。
- 实际稀疏度仍然 Data-dependent（依赖数据），校准保证的是统计稳定性，不是每条请求的硬计算预算或 Worst-case Service-level Objective（最坏服务等级目标）。
- Block 决策需要相关 Row 一致同意；若一个 Row 需要该 Tile，其他 Row 也会一起计算，硬件友好但牺牲可达到的细粒度稀疏率。
- BLASST 的优势集中在 Causal LLM 和 Decode；Sol-Attn 当前的近似推导假设 Block 内 Dense、Non-causal Key。把 Sol-Attn 扩展到 Autoregressive Decode 还需处理 Causal Valid-key Multiplicity、Streaming KV Pooling、GQA/MQA 共享 KV、Attention Sink 和不规则 Nested Loop。
- Kernel Speedup 与端到端收益差距明显；部署前应按真实 Context、Batch、并发和 Attention 占总时间比例重新测量。

## 我的判断

BLASST 不是把注意力变成次二次复杂度的算法突破，而是一篇很成熟的 Algorithm-Kernel Co-design（算法与核函数协同设计）工作：它复用必算的 Online Softmax 统计量，让路由成本几乎消失；稀疏粒度与 FlashAttention Tile 完全对齐；并针对 Compute-bound Prefill 与 Memory-bound Decode 分别删除真正的瓶颈资源。它最值得学习的是“在已有关键路径里寻找免费控制信号”，而不是 Threshold 公式本身。

对 Sol-Attn 而言，两者共享“On-the-fly Thresholding、不物化完整路由图”的系统叙事，但 Sol-Attn 解决的是更早一层的问题：用 Pooled Proxy 跳过 Exact BMM1，并复用同一 Proxy Tile 对 Tail Block 做 Approximate Correction（近似补偿）。最稳妥的公开定位是：

> Unlike BLASST, which performs late pruning after computing dense exact QK scores and discards rejected blocks, Sol-Attn performs early routing with pooled KV proxies, avoids exact QK computation for rejected blocks, and reuses the same proxy-score tile to approximate their softmax contribution.

截至阅读时，Sol-Attn 公开 v1 的 Related Work 与 References 中未检索到 BLASST。下一版应补充引用，并避免把宽泛的“Online-softmax Thresholding”单独作为首要新颖性；更强的主张是：**Early Proxy Routing、Subquadratic Exact Computation 与 Tail Correction 被融合进一个 Nested Online-softmax Operator。**

BLASST 也给 Sol-Attn 两个直接启发：若将来扩展到 AR/LLM，应借鉴它的 Decode Conditional-$V$-load 与 Batched Scheduling；若增加训练版本，可以像 BLASST 一样让训练 Forward 与部署时的 Sparse Operator 完全一致。

## 下次只看这些

1. BLASST 是 Exact $QK^\top$ 之后的 Late Pruning：路由近乎免费且适用 LLM Decode，但 BMM1 全保留，Kernel 上限约 $1.8\times$。
2. Sol-Attn 是 Pooled Proxy 之前的 Early Routing 加 Exact-or-Approx Correction：能跳过完整 $QK^\top$，这是两篇工作最本质的边界。
3. Sol-Attn 下一版补引 BLASST，并把主张集中在 Nested Operator、Query-dependent Density Control 和 Proxy Reuse Correction，而不是泛化的 Online Thresholding。
