## 研究问题

传统 speculative decoding 用小模型逐 token 起草，再让大模型并行验证；虽然验证阶段并行，EAGLE-3 等强方法的 drafting 仍是 autoregressive，起草 $\gamma$ 个 token 需要 $\gamma$ 次串行 forward，容易成为新的延迟瓶颈。已有 diffusion drafter 可以并行生成 token block，但独立小模型既缺容量又不了解 target 的内部判断，接受长度有限；直接使用 7B 级 diffusion model 又会让 drafting 本身过重。

DFlash 要解决的是：能否训练一个很浅、但能读取 target 内部表征的 block-diffusion drafter，一次 forward 并行提出多个未来 token，同时继续依靠标准 target verification 保持 lossless decoding？

## 核心方法

- **Target-specific drafter**：DFlash 不是随便找一个现成小语言模型，也不是从 Qwen3-8B 截下几层。它是单独训练的浅层 Transformer；target 全程冻结，drafter 与 target 共享并冻结 token embedding 和 LM head，只更新 draft Transformer layers。
- **读取 activation，不是复制权重**：target 在 prefill 和 verification 中正常运行，DFlash 读取若干 target Transformer 层对当前已确认上下文产生的 hidden states。以官方 Qwen3-8B-DFlash-b16 为例，36 层 target 使用 layer IDs $[1,9,17,25,33]$；每个位置从浅层到深层得到五个 4096 维向量。
- **先聚合多层 target feature**：五层 hidden states 沿 channel 维拼接，再通过一个共享 projection 和 RMSNorm 压回 draft hidden dimension：

$$
\mathbf H_t=\operatorname{RMSNorm}\!\left(
W_c[\mathbf H^{(l_1)};\ldots;\mathbf H^{(l_5)}]
\right).
$$

  若 prefix 长度为 $L$、hidden size 为 4096，输入由五个 $[L,4096]$ 拼为 $[L,20480]$，再投影成 $\mathbf H_t\in\mathbb R^{L\times4096}$。这是可学习的融合，不是平均。
- **向每一层 drafter 做 KV injection**：融合后的同一份 $\mathbf H_t$ 不是只进入 DFlash 第一层，而是成为每一层 attention 都能读取的额外 memory。第 $i$ 个 draft layer 使用自己的投影：

$$
\begin{aligned}
\mathbf Q_i &= W_i^Q\mathbf H_d,\\
\mathbf K_i &= [W_i^K\mathbf H_t;W_i^K\mathbf H_d]_{\mathrm{seq}},\\
\mathbf V_i &= [W_i^V\mathbf H_t;W_i^V\mathbf H_d]_{\mathrm{seq}}.
\end{aligned}
$$

  target features 只提供额外 K/V，不经过 draft layer 的 Q projection、output projection、self-attention update 或 FFN。对应 K/V 被保存在 draft model 的 KV cache 中复用；五层 DFlash 会分别用自己的 $W_i^K,W_i^V$ 解读同一份融合信息。
- **一次并行预测一个 block**：默认 block size 为 16。每轮以上一次 target verification 给出的 clean bonus token 作为 anchor，后接 15 个 mask；block 内 token 双向 attention，drafter 一次 forward 同时预测后 15 个位置，然后 target 一次并行验证并接受正确前缀。
- **贴合 inference 的训练**：从 Nemotron Post-Training Dataset V2 和 CodeAlpaca 采约 800K prompts，用 target 自己重生成 responses。训练时随机选 response 中的 anchor，mask 后续 $\text{block\_size}-1$ 个位置；target hidden features 可在线计算，也可预先离线缓存。
- **强调 block 前部准确率**：前面一个 token 错误会使后续 draft 全部失效，因此第 $k$ 个位置的交叉熵权重指数衰减：

$$
w_k=\exp\!\left(-\frac{k-1}{\gamma}\right),
$$

  使训练优先提高最影响 accepted prefix 的早期位置。

## 关键发现

- 在 Qwen3-8B、temperature 0 的七项 math/code/chat 评测中，DFlash-b16 平均达到 **4.86× speedup、6.49 accepted tokens**；EAGLE-3 的 60-token tree 为 **2.02×、3.40**。DFlash 在 MATH-500 上达到 **6.08×**。
- Temperature 1 时，Qwen3-8B 上 DFlash 仍平均达到 **4.03×、5.48 accepted tokens**，EAGLE-3 60-token tree 为 **1.88×、3.26**。
- Draft depth 与 target feature 数是两个独立超参数：固定使用 5 个 target features 时，8-layer drafter 接受长度更长，但 5-layer drafter 的平均 wall-clock speedup 更好；固定 3-layer drafter 时，5 个 target features 又一致优于 3 个。
- KV injection 的作用不是装饰。Qwen3-4B、5-layer drafter、block size 8 的 ablation 中，block-diffusion DFlash 在 GSM8K 上由 input-only fusion 的 **$\tau=3.5$/2.9×** 提升到逐层 KV injection 的 **$\tau=4.2$/3.3×**，HumanEval 和 MT-Bench 也一致改善。
- 完全不使用 target features 的 5-layer diffusion drafter 在数学任务上通常只有约 **2–3×** speedup，说明轻量 drafter 的关键不只是 block parallelism，还在于复用 target 已经形成的上下文判断。

## 我的提问

### Q1：DFlash 的 draft model 到底是怎么来的？

它不是直接拿一个 Qwen 小兄弟，也不是把 Qwen3-8B 的五层拆出来。它是为指定 target 单独训练的 5-layer block-diffusion Transformer；Qwen3-8B 冻结并提供训练目标、embedding、LM head 和运行时 hidden features，DFlash 自己的 Transformer layers 负责学习如何利用这些信息并行预测 mask block。论文和当前公开仓库没有明确说明 draft layers 是随机初始化还是从 target 层复制初始化，记为待补充。

### Q2：所谓“从 Qwen3-8B 拿五层 feature”，拿的究竟是什么？

拿的是 Qwen 正常 forward 时各层输出的 hidden-state activation：对当前 prefix 中的每个 token，都有一个描述该位置在整段上下文中含义的向量。它不是 Qwen 层权重、最终 logits、已经生成好的未来 token，也不是直接复制 Qwen 原始 KV cache。五层 activation 先融合为 $\mathbf H_t$，再由 DFlash 每层自己的 K/V projection 转成可 attention 的 memory。

### Q3：五个 Qwen features 与五层 DFlash 是否一一对应？

没有。前一个“5”表示从 target 取几个深度的表征，后一个“5”表示 drafter 自己做几层计算。五个 target features 先融合成一份 $\mathbf H_t$，然后注入全部 draft layers，不存在 Qwen layer 1 对 DFlash layer 1、Qwen layer 9 对 DFlash layer 2 的映射。论文也实际组合了 3/5/8 层 drafter 与 5 个 target features，证明两者可以独立改变。

### Q4：为什么不让五层 DFlash 分别只看一层 Qwen feature，省掉 aggregation？

这个设计可以实现，也是值得补做的 ablation，但论文没有直接比较。强制一一对应会人为绑定两个独立超参数，并假设浅层 Qwen 信息只适合浅层 DFlash、深层信息只适合深层 DFlash；两套网络没有这种天然层语义对齐。当前设计让每个 draft layer 都能同时利用词法、语义和接近最终预测的深层信息，再通过各自的 $W_i^K,W_i^V$ 形成不同读法。

更灵活的替代方案是每个 DFlash layer 分别学习对全部 target layers 的 aggregation；它可能更有表达力，但会增加 projection 参数、特征构建和缓存复杂度。现有 shared aggregation 是信息完整性、结构解耦与开销之间的折中，不能仅凭论文结果断言它优于所有逐层映射方案。

### Q5：这对 video speculative decoding 最直接的借鉴是什么？

不要默认拿一个独立的 1.3B video model 给 14B model 起草。更接近 DFlash 的路线，是训练一个 target-specific 的浅层 block drafter：读取 14B video DiT 的多层 context features，将融合结果注入 draft DiT 每一层的 KV，再并行预测未来 latent/video blocks。这样 drafter 不必从 prompt 和历史视频重新独立理解场景。

但 LLM 的 target verification 可以相对廉价地批量检查 token；video DiT 往往更 compute-bound。只有 target feature 能从本来就要做的 prefill/verification 中顺手取得，且验证多个 video blocks 明显低于逐 block target generation，才可能形成真正 wall-clock 加速。否则 feature-conditioned drafter 更适合作为 target-skipping router 或局部 refinement proposal，而不一定适合照搬 lossless token verification。

## 局限与疑问

- 当前论文和公开仓库没有交代 draft Transformer layers 的具体初始化来源；要严谨复现仍需等待官方 training recipe。
- 论文比较了 3 vs. 5 个 target hidden features、不同 draft depth，以及 input fusion vs. KV injection，但没有比较“一层 target feature 对一层 draft layer”或“每个 draft layer 独立聚合全部 target features”。
- 五层 feature 的离线缓存存储随 feature 数线性增长；在线训练则需要在每步运行冻结 target。约 800K target-generated responses、最长 3072/4096 token 的训练仍不是低成本 adaptation。
- headline speedup 依赖硬件、backend、batch/concurrency、block size 和任务可预测性。较深 drafter虽然提高接受长度，却可能因 drafting latency 更高而降低端到端速度。
- “Target knows best”依赖 target hidden states 确实含有可读出的多 token future information；开放式高熵对话的接受长度明显低于数学和代码，不能把 6× 当成普遍结果。
- KV injection 会让 drafter 与特定 target 架构、hidden dimension 和表示空间紧耦合；更换 target 或显著微调 target 后通常需要重新训练或至少重新适配 drafter。

## 我的判断

DFlash 最值得借鉴的不是“diffusion 一次出 16 个 token”这一表面形式，而是把 drafter 从独立小模型重新定义为 **读取 target 内部状态的轻量并行 adapter**。它同时解决两个瓶颈：block diffusion 消除 autoregressive drafting 的串行次数，逐层 KV injection 又补偿小模型容量不足。论文的独立 ablation 能较清楚地支持这两个机制，结构也足够具体，值得作为 target-conditioned speculative drafting 的强 baseline。

对当前 video generation 方向，最有研究价值的是 multi-layer target feature conditioning：训练浅层 video drafter 或 router 时，让它直接读取大 DiT 已形成的语义、运动和时序表征，而不是要求小模型从头复现大模型能力。但必须先测量 target feature 获取、KV injection、parallel verification 和 latent block size 的真实延迟；视频场景如果不能廉价 verification，DFlash 的高接受率并不会自动变成端到端加速。

下一步最有价值的实验不是简单复制五对五结构，而是比较 shared aggregation、target/draft layer 一对一映射、per-draft-layer aggregation 三种 feature routing，并同时报告 acceptance length、draft latency、target verification scaling 和显存开销。

## 下次只看这些

1. Qwen 多层 feature 是运行时 hidden-state activation，不是拆层或复制权重；五个 features 与五层 drafter 是独立超参数。
2. 五层 target features 先融合成一份 $\mathbf H_t$，再作为额外 KV 注入 DFlash 的每一层；这不是只在第一层输入一次。
3. 对 video 的关键借鉴是 target-conditioned shallow drafter，但先验证 compute-bound target 是否能廉价批量 verification，否则应转向 target-skipping 或局部 refinement。
