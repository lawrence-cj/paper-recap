## 研究问题

视频 VAE 压得越小，DiT 每步处理的 token 越少，生成越快。但提高时空压缩率会丢失信息；增加 latent 通道能补回一部分信息，却又改变原 DiT 熟悉的表示，增加适配难度。只优化 VAE 的重建质量，不能保证这种 latent 容易被预训练 DiT 生成。

GRACE 研究如何同时复用已有 VAE 和 DiT，在较少的额外训练下提高压缩率。实验以 Wan2.1-14B 为基础，把 f8t4 改为 f16t8，DiT 的空间 patch 仍为 2×2。它降低每一步的计算量，推理仍用 50 个采样步。

阅读依据：[论文 v1，2026-10-07](https://arxiv.org/html/2610.10524v1)、[项目页](https://cvlab-kaist.github.io/GRACE/)、[官方代码](https://github.com/cvlab-kaist/GRACE)。实验数字统一采用论文 v1；项目页部分消融行的 I2V 分数与 PDF 略有差异。

## 核心方法

![GRACE 两阶段训练：冻结原 encoder 和 DiT 主干训练双 latent VAE，再冻结 VAE 并通过 LoRA 适配 DiT](media/grace/method-overview.webp "论文 Figure 2：GRACE 总体架构，上半部分训练 VAE，下半部分适配 DiT。来源：Jiyoung Kim et al., GRACE，arXiv:2610.10524v1，第 5 页，https://arxiv.org/html/2610.10524v1#S4.F2；CC BY 4.0，https://creativecommons.org/licenses/by/4.0/；从 PDF 裁取架构图并无损转为 WebP，未改动图内内容。")

- **先训练 VAE。** 冻结原始 encoder $E$ 和 DiT 主干，把视频空间缩小两倍、时间隔帧采样后交给 $E$，得到 16 通道 base latent；完整视频交给可训练的 residual encoder $E_{\mathrm{res}}$，得到另 16 通道。两者沿通道拼接，交给同一个可训练 decoder $\hat D$ 重建完整视频。

$$
z_{\mathrm{base}}=E(x_{\mathrm{low}}),\qquad
z_{\mathrm{res}}=E_{\mathrm{res}}(x),\qquad
z=[z_{\mathrm{base}};z_{\mathrm{res}}],\qquad
\hat x=\hat D(z).
$$

$x$ 是完整视频，$x_{\mathrm{low}}$ 是降采样视频，分号表示通道拼接。Base 保留原 encoder 的表示，residual 学习补充降采样丢失的信息；这里没有像素相减，也没有给两组 latent 各配一个 decoder。

- **用旧 DiT 的中间 feature 指导压缩。** 完整视频还经过原 encoder 得到 $z_{\mathrm{pre}}=E(x)$，作为参照。$z_{\mathrm{pre}}$ 和压缩后的 $z$ 使用同一个噪声时间、独立噪声，分别进入共享冻结主干的 DiT。压缩分支扩展输入投影以接收新增通道，取前 10 层 feature，恢复时空网格后用三线性插值对齐尺寸，再经小型残差投影，与原分支 feature 比较。

$$
\mathcal L_{\mathrm{align}}
=\sum_{l=1}^{10}\left[1-\operatorname{sim}\left(h_{\mathrm{pre}}^l,\hat h_{\mathrm{cmp}}^l\right)\right],\qquad
\mathcal L=\mathcal L_{\mathrm{recon}}+w_{\mathrm{adaptive}}\mathcal L_{\mathrm{align}}.
$$

$h_{\mathrm{pre}}^l$ 是原分支第 $l$ 层特征，$\hat h_{\mathrm{cmp}}^l$ 是经过插值和投影的压缩分支特征，$\operatorname{sim}$ 为逐 token 余弦相似度的平均。重建损失包含 L1、LPIPS 和 KL；两项损失按 residual encoder 最后卷积层上的梯度范数比动态配权。参照特征不更新，残差编码器、decoder、扩展输入投影和特征投影参与训练。

- **再冻结 VAE，适配 DiT。** 扩展输入输出层，使用 LoRA 微调 attention 和 FFN，同时更新相关调制与归一化参数。训练目标是 flow matching；base 和 residual 在同一次 forward 中联合预测，但 base 的噪声更小、去噪进度更靠前。

$$
u_{\mathrm{base}}=\max(\hat u-\delta,0),\qquad
u_{\mathrm{res}}=\min(\hat u,1).
$$

$u=1$ 为纯噪声，$u=0$ 为干净表示，训练时 $\delta\sim\mathcal U(0,0.6)$、$\hat u\sim\mathcal U(0,1+\delta)$，再通过同一个 flow shift 函数映射到实际噪声时间。推理固定 $\delta=0.15$：开头几步只更新 base，结尾几步 base 已固定、继续更新 residual；整体仍是同一条 50 步采样过程。

训练顺序的细节：Stage 1 先在 $256\times256\times81$ 更新 residual encoder 和 decoder，再在 $512\times512\times81$ 冻结 encoder、只适配 decoder；Stage 2 在 $480\times832\times81$ 训练 DiT，LoRA rank 为 512。压缩后 RoPE 的空间和时间索引均放大两倍，base 与 residual 分别统计并标准化。T2V、I2V 分别训练各自的 VAE 和 DiT 适配版本。

## 关键发现

在 $480\times832\times81$ 下，原 latent 为 $16\times21\times60\times104$，GRACE 为 $32\times11\times30\times52$，维度顺序是通道、时间、高、宽。经空间 2×2 patch 后，token 从 32,760 降为 4,290，实际为约 7.64 倍；因果首帧使有限长度视频不是严格八倍。通道数翻倍，因此 latent 元素总数约减少 3.82 倍，不能把 token 减少八倍直接当成存储减少八倍。

以下为论文 Tables 2–4 的结果。480p 指 $480\times832\times81$，736p 指 $736\times1280\times81$。

| 指标 | 原始 Wan2.1-14B | GRACE |
| --- | ---: | ---: |
| 480p I2V 延迟 | 863.2 秒 | 77.7 秒，约 11.1× 加速 |
| 736p I2V 延迟 | 3396.8 秒 | 218.8 秒，约 15.5× 加速 |
| 480p VBench-T2V 总分 | 83.93 | 85.81 |
| 480p VBench-I2V 总分 | 87.92 | 87.90 |

测试使用单张 A100 SXM4 80GB、bf16、batch 1、50 steps、CFG 5。Wan 与 GRACE 均为每视频 100 次 DiT forward。延迟包含条件图像编码、去噪和视频解码，不含模型加载、文本编码和写 MP4。

| 同一压缩配置下逐步加组件 | VBench-T2V 总分 | VBench-I2V 总分 |
| --- | ---: | ---: |
| 普通单 latent 压缩 | 82.12 | 86.44 |
| 加双 latent | 83.55 | 86.64 |
| 再加 DiT 特征对齐 | 84.68 | 87.51 |
| 再加非对称去噪 | 85.81 | 87.90 |

- **压缩带来速度，三个组件补回生成质量。** 普通压缩 baseline 的 I2V 延迟已经是 77.8 秒，与 GRACE 的 77.7 秒接近。
- **重建更好不等于生成更好。** 普通压缩 baseline 的 PSNR 为 33.76 dB，高于 GRACE 的 32.63 dB，但生成总分更低。
- **VBench 接近不等于视觉无损。** 附录 D.2 的 39 人盲评中，T2V 画面质量偏好 GRACE / 持平 / Wan 的比例为 49.4% / 15.4% / 35.3%；I2V 为 23.7% / 32.7% / 43.6%，仍偏好原 Wan。
- **额外训练有明确成本。** 每个任务合计 38.5 H200 GPU 天，其中 VAE 8.5、DiT 30；不包含原始 Wan 的预训练成本。

## 我的提问

### Q1：训练顺序和 feature 使用方式，high level 怎么理解？

先让新 VAE 产生更小、又与原 DiT 相容的表示，再让 DiT 学会生成它。第一阶段 DiT 是冻结的特征提取器，原 latent 的中间 feature 提供监督；压缩 latent 的 feature 插值到同样的时空尺寸后与之对齐。第二阶段 VAE 已固定，DiT 才开始适配。原分辨率参照分支和 feature 对齐只服务训练，推理不额外跑一遍教师分支。

### Q2：最终 base 和 residual 的 encoder-decoder 是一起用的吗？

最终 VAE 有两个编码分支和一个共同使用的 decoder。训练或重建时，两路 encoder 分别得到 base 与 residual，沿通道拼接后由同一个 decoder 还原视频；不需要先各自解码再相加。

真正 T2V 生成时没有完整视频可编码，两组 latent 都由 DiT 从噪声中联合生成，再交给同一个 decoder。I2V 仍需处理输入图片并提供首帧条件，但不会编码尚未生成的未来视频。

生成流程是：随机噪声 → DiT 生成 $[z_{\mathrm{base}};z_{\mathrm{res}}]$ → 同一个 decoder → 完整视频。

### Q3：冻结 base encoder，是不是意味着生成时 base latent 也固定？

冻结的是训练期间 encoder 的参数。Base latent 在生成时仍要由 DiT 去噪得到；它只是比 residual 更早变清楚。两者共同进入一次 forward，不是先生成一段低清视频，再启动另一套模型补细节。

## 局限与疑问

- 高压缩对远处人脸、文字和细线条不友好；I2V 人工偏好也显示原模型的画面质量和时间一致性更好，不能称为无损压缩。
- 主要验证对象是 Wan2.1-14B 和 81 帧视频。其他 backbone、长视频与更复杂运动的收益仍待验证；训练预处理还过滤了切镜和过大运动的片段。
- VAE 与特定 encoder、DiT 的表示绑定。迁移到新模型仍需要重新训练；并非任意 VAE 的即插即用替换件。
- 与原 Wan 的比较较直接；跨 LTX、Open-Sora 的比较还涉及模型、训练数据、prompt 扩写和 guidance 分支数差异，应与同 backbone 的消融分开理解。
- residual 的分工是学出来的，并没有保证只含高频信息；特征对齐和去噪顺序的效果来自实验支持。

## 我的判断

本次讨论最重要的澄清是：两个 encoder 用于构造训练表示，生成时 DiT 负责产生两部分 latent，decoder 始终共同读取它们。把训练图直接当成推理流程，会误以为还需要完整输入视频，或把 base 当成固定条件。

从技术上看，值得记住的是“让 VAE 兼顾已有生成器是否容易学习”，以及保留部分旧表示以降低适配成本。对已有大模型的压缩改造，这种思路有参考价值。实际取舍应同时看计算成本、细节和人工偏好，不能只以 VBench 总分判断质量保持。用户是否计划复现或采用：待补充。

## 下次只看这些

1. 先训 VAE、再适配 DiT；feature 对齐用冻结 DiT 的前 10 层，只在训练需要原分辨率参照分支。
2. 重建用两个 encoder、一个 decoder；生成由 DiT 联合产生 base 和 residual，再交给同一个 decoder，base 去噪领先。
3. 约八分之一 token 换来 11.1× 加速；I2V VBench 接近，但人工评价和小尺度细节仍有损失。
