## 研究问题

MiniMax H3 的 softmax attention 占推理耗时 85% 以上，是视频生成推理侧的主要瓶颈。VDN-H3（代码：`github.com/OpenVDN/vdn-minimax-h3`，权重：`huggingface.co/OpenVDN/vdn-minimax-h3`）要解决的问题是：能否把一个已经训好的 dense 视频 DiT 蒸馏/线性化成 hybrid attention 模型，在几乎不损失质量的前提下大幅加速，而不是从零训练一个新架构（对比组是同期的 SANA-Video 2.0，后者选择从零训练）。

我最初的疑问是：印象中 hybrid attention（softmax+linear 混合）模型效果普遍不如纯 softmax，这篇工作具体是怎么把质量做回来的？

## 核心方法

- **Intra-layer hybrid，不是 depth-level hybrid**：每一个 DiT block 内部并行跑两条分支——sliding-window softmax + 双向 linear attention（Video Delta Attention, VDA）——两者的输出各自过 gate 后相加进残差流。这与 SANA-Video 2.0"整层要么纯 softmax、要么纯 linear，按 3:1 比例周期性交替"的 depth-level 设计是两条不同路线。
- **Softmax 分支是 chunk 对齐的局部滑窗，不是全局 attention**：帧按 5 帧一组分 chunk（`chunk=5, radius=1`），每个 chunk 只看自己+前一个+后一个 chunk（≤15 帧），双向非因果。为了不丢全局信息，`anchor_frames="both"` 让首尾两帧在两个方向上都是精确的全局 softmax，只占约 3.57% 的额外 attention 密度。
- **Linear 分支（VDA）逐帧求解，不是逐 token 递归**：把每帧 S 个 token 的 K/V 先压成两个 $d\times d$ 统计量 $A=K^\top\mathrm{diag}(\beta)K$、$B=V^\top\mathrm{diag}(\beta)K$，再用批量 Cholesky 精确求解（`vdn_solve`，released checkpoint 默认规则）：

$$
S_t=\big(S_{t-1}\,\mathrm{diag}(\alpha_t)+B_t\big)(I+A_t)^{-1},\qquad
\alpha_t=\exp\!\big(-e^{A_{\log}}\cdot\mathrm{softplus}(\delta_t+b)\big)
$$

  维护两条独立 scan（forward `prefix_states` / reverse `suffix_states`），对查询帧 $t$，取窗口外的状态并按 $\alpha$ 累积衰减"搬运"过来，天然互补 softmax 窗口覆盖不到的长程上下文。prompt 被当一整帧一次性写入初始状态 $S_{\text{text}}$，两个方向都从 $0.5\,S_{\text{text}}$ 起步，保证窗口触边时读到的是 prompt 而不是空。
- **两个 gate 初始化策略相反**：两分支间的 `softmax_gate` 常数初始化在 0.99（per-head），训练一开始整层输出≈原始教师输出；linear 分支自己的 `output_gate` 是低秩、随机初始化、从 step 0 就是活的路由门。这个不对称是防止"优化器抄近道，把混合门关掉、只留 softmax 分支"的关键设计。
- **四阶段渐进解冻蒸馏训练**（不是官方 blog 描述的三阶段——代码里还有第四段 Stage DMD）：

  | Stage | 训练对象 | Steps | loss / 目标 | gate 状态 |
  |---|---|---:|---|---|
  | A1 | 新增 linear 分支，逐层单独训 | 200 | 每层归一化 MSE：$\lVert f_\theta-f_{\text{teacher}}\rVert_2^2/\lVert f_{\text{teacher}}\rVert_2^2$ | softmax_gate 锁 0.99 |
  | A2 | 全部 linear 分支端到端联调 | 500 | 整模型 velocity 蒸馏教师（非真实 x0-noise） | softmax_gate 锁 0.99 |
  | B | QKVO LoRA(r=64)+linear 分支+**softmax_gate 解冻** | 2000 | 同样蒸馏教师 velocity，可选混入小权重真实 diffusion loss 做正则 | 解冻联合训练 |
  | DMD | few-step "turbo" LoRA，DMD2(无GAN) | 250 | distribution matching：real score(冻结 VDN) vs fake score | Stage-B LoRA 冻结但全程 active |

  A1 用逐层归一化 MSE 是因为不同层教师输出数值尺度差几个数量级，不归一化梯度裁剪会失效；A2/B 换成整模型蒸馏教师自身的 velocity 预测（而非真实数据的 x0-noise），理由是真实数据目标的方差主要来自单样本采样噪声，教师输出方差小得多，训练信号更干净。
- **学习率按 fan-in 分组（muP 式）**：`alpha.down`/`beta_proj`/`to_out_linear`/`softmax_gate` 这类直接吃完整 hidden_size 的宽矩阵是 "big" 组；`alpha.up`/`output_gate.up`/norm gain/depthwise 卷积核这类吃窄瓶颈（如 head_dim）或逐 channel 的参数是 "small" 组，学习率放大 2~5 倍且单独设置更小的 AdamW eps，防止窄 fan-in 参数被宽矩阵的更新节奏拖慢。
- **few-step turbo LoRA 复用社区权重，非自训**：DMD 阶段的 "turbo" adapter 初始化自第三方 `larryvrh/MiniMax-H3-Turbo-Lora`（针对 dense H3 训练的加速 LoRA），再用 DMD2 继续训练。关键是训练时 Stage-B 的 "default" LoRA 全程冻结但保持 **active**（`Roles` 表：generator = `[default, turbo]` 同时生效），所以 turbo 学到的是"在 default 已生效的前提下再叠加什么修正"，而不是独立训好再盲目拼接。推理阶段两个 LoRA 按同一套加性规则合并进同一权重：

$$
W_{\text{final}}=W_{\text{base}}+s_{\text{default}}(B_{\text{default}}A_{\text{default}})+s_{\text{turbo}}(B_{\text{turbo}}A_{\text{turbo}})
$$

  因为二者目标模块完全相同（`attn.orig.to_q/k/v/o` 等），两个低秩修正可以直接相加，这在数学上天然成立；"兼容"不是巧合，是训练目标函数本身就围绕这个组合定义的（DMD 的 real score 用 `[default]`，即 "generator 减去 turbo"，直接以两者的分布差作为 turbo 的训练信号）。

## 关键发现

- 8×B200，14.4 秒视频片段：dense H3 需 13.95 分钟（单卡，50 NFE），VDN-H3 FP8 单卡 5.3 分钟，8 卡分布式 1.2 分钟；8 NFE 配置下 8 卡分布式仅需 **11.23 秒**——比视频本身播放时间还短。
- softmax : linear 的 attention 密度大致 52% : 48%（典型 workload），boundary anchor 只额外增加 3.57% 密度。
- 完整训练流程共 **2950 步**（A1 200 + A2 500 + B 2000 + DMD 250），大头在 Stage B；A1/A2 相对官方描述的"轻量对齐"确实很短。
- Stage A1/A2/B 都需要真实的预编码视频/音频/文本 latent 作为输入（`H3LatentT2VADataset`），但监督信号来自冻结教师在同一输入上的预测，不是真实标签；只有 Stage DMD 完全不需要视频数据，靠 prompt + 模型自身 rollout 生成训练样本。
- 仓库未公开原始视频数据集的来源、规模或许可，只给出预处理后 latent 的目录格式，需要用户自备数据。

## 我的提问

### Q1：VDN-H3 和同期的 SANA-Video 2.0 架构上最大的区别是什么？

SANA-Video 2.0 是 depth-level hybrid：整层要么纯 linear、要么纯 softmax anchor，按 3:1 周期交替排布，并额外用 Block Attention Residuals（AttnRes）把已完成 block 的摘要路由进后续 linear 层，补偿被跳过层的 rank 损失；且从零训练整个架构。VDN-H3 是 intra-layer hybrid：每一层内部两条分支并行、gate 加权求和；是把已有 dense H3 蒸馏/线性化得到，不是从零训练。

### Q2：局部滑窗 softmax 还能叫"hybrid attention能保留全局质量"吗？它跟原始全局 softmax 不等价吧？

确实不等价，博客本身也承认"linear attention struggles to maintain global features"这个矛盾。VDN-H3 靠三样东西拼回全局感受野：chunk 滑窗保证近邻精确交互、boundary anchor 给一条低成本全局广播/收集通道、双向 linear state 的 forward/reverse scan 负责窗口外的长程上下文（且 prompt 状态会同时写入两个方向）。没有理论上的感受野等价性证明，只有"生成视频与原始 H3 几乎无法区分"这个经验结论支撑。

### Q3：每一层里 softmax 和 linear 分支具体是怎么联合训练/适配的？

不是端到端从零联合训练，是四阶段渐进解冻：A1 逐层单独训 linear 分支（softmax_gate 锁 0.99，防止优化器抄近道直接关掉新分支）；A2 端到端联调 linear 分支（gate 仍锁）；B 才解冻 softmax_gate，同时加 QKVO LoRA 联合训练；DMD 单独蒸馏 few-step LoRA。gate 的两种初始化（softmax_gate 常数 0.99 vs linear 分支 output_gate 随机初始化即时生效）是这套 pipeline 能稳定收敛的关键细节。

### Q4：Stage A/B 是不是模型自己生成数据在训自己（左脚踩右脚）？

不是。A1/A2/B 都读取真实视频/音频/文本预编码 latent 作为输入，只是**监督信号**换成了冻结教师在同一输入上的预测（教师蒸馏），不是真实数据的 ground truth。真正"数据无关、模型自产训练样本"的只有 Stage DMD——它只需要 prompt，训练样本靠 generator 自己从纯噪声 rollout 出来。

### Q5：DMD 阶段的 few-step "turbo" LoRA 是团队自己训的吗？两个 LoRA（Stage-B 的 default + DMD 的 turbo）怎么保证能一起工作？

不是自己从零训的，初始化自第三方社区权重 `larryvrh/MiniMax-H3-Turbo-Lora`（本来是给 dense H3 训的加速 LoRA），再用 DMD2 继续微调。两者能"兼容"不是运气：训练时 default LoRA 全程冻结但在前向图里保持激活，turbo 的每一次梯度更新都是在"default 的贡献已经真实存在"的条件下算出来的；DMD 的训练目标本身就是 `[default+turbo]` 与 `[default only]` 两个分布之间的差距，天然把"组合关系"绑进了 loss 里。推理时两者按同一套 `W += B@A` 规则加性合并进同一权重矩阵。

## 局限与疑问

- 感受野从"全局 softmax"退化为"局部滑窗+anchor+linear state"缺乏理论等价性证明，官方只给了定性的"几乎无法区分"，没有公开 VDN-H3 vs dense H3 的量化质量指标（如 VBench 分数）对比，只有速度数字。
- 原始视频训练数据的来源、规模、许可完全没有公开，只有预处理后 latent 目录格式，可复现性受限于用户自己能拿到什么级别的数据。
- Blog 里"三阶段训练"的表述和实际开源代码的"四阶段"（多了 Stage DMD）不一致，需要读代码才能发现，说明公开材料本身有简化/遗漏。
- few-step 版本的效果上限部分依赖一个非自训的第三方 LoRA（`larryvrh/MiniMax-H3-Turbo-Lora`）的质量，如果这个外部 LoRA 本身有局限，DMD 阶段是在其基础上做二次适配而非从头设计。

## 我的判断

这套四阶段"渐进式解冻+教师蒸馏"pipeline（逐层对齐锁 gate → 端到端联调锁 gate → LoRA+gate 联合解冻 → few-step 蒸馏）是可复用的工程模板，尤其两个细节值得记住：新分支初期必须让 gate 焊死在教师侧，否则优化器会抄近道把新分支饿死；lr 要按 fan-in 分组缩放，窄瓶颈参数不加速会被宽矩阵拖慢收敛。它回应了我最初"hybrid 效果不理想"的担忧——不是架构本身天然更差，而是需要局部精确 attention + 全局 anchor + 双向 linear state + 细致的分阶段蒸馏配方来补偿，是工程补救到位的案例，不构成"hybrid 天生可行"的架构级证明，质量保证目前仍主要靠训练配方撑着而非理论保证。

## 下次只看这些

1. VDN-H3 是 intra-layer hybrid（每层并行 softmax+linear 双分支，两个 gate 初始化策略相反），不是 SANA-Video 2.0 那种 depth-level 整层交替；softmax 只是 chunk 滑窗+boundary anchor，不等价于原始全局 softmax，靠双向 linear state 和 anchor 补全局。
2. 真实训练是四阶段共 2950 步（A1 200 逐层蒸馏锁 gate → A2 500 端到端蒸馏锁 gate → B 2000 LoRA+gate 解冻联合训练 → DMD 250 few-step 蒸馏），A/B 阶段吃真实视频 latent 但监督来自教师输出，只有 DMD 完全 data-free。
3. few-step turbo LoRA 复用第三方社区权重做初始化，靠"训练时 Stage-B LoRA 冻结但全程 active"的前向图设计，把两个 LoRA 的组合关系结构性地绑进训练目标，而不是训完各自再盲目拼接。
