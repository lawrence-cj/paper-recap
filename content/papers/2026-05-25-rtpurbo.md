## 研究问题

长上下文 LLM 的 attention 成本随序列长度快速增长，但不同 head 和不同 query 对历史 token 的依赖高度不均匀。固定稀疏率容易在简单样本上浪费计算、在困难样本上损失质量，论文希望按 query 动态决定实际需要读取多少 token。

## 核心方法

- 先识别真正承担长程检索的少量 retrieval heads，其余 heads 保持原有计算路径。
- 用低维索引器近似 query-key 相关性；历史记录中的实现使用 16 维表示，避免先做完整 attention 才知道哪些 token 重要。
- 按累计相关质量执行动态 top-p 选择，而不是给所有请求设置同一个 top-k：

$$
\mathcal S(q)=\min\left\{S:\sum_{i\in S}p_i(q)\ge p\right\},
\qquad
p_i(q)=\frac{e^{s_i(q)}}{\sum_j e^{s_j(q)}}.
$$

当相关性集中时集合 $\mathcal S(q)$ 很小；相关性分散时自动保留更多 token。
- 通过少量 post-training 和 self-distillation，让索引器及稀疏路径尽量保持原模型能力。

## 关键发现

- 历史记录中的论文结果显示，1M token prefill 最高约 **9.36×** 加速，decode 约 **2.01×**。
- 关键收益来自“只稀疏需要检索的 heads”与“每个 query 动态预算”的组合，而非单纯固定比例裁剪 KV。

## 我的提问

### Q1：它能否直接用于 LTX-2.3 这类视频生成模型？

不能原样照搬。RTPurbo 面向 LLM 的长上下文检索，视频 DiT 的 token 具有强局部时空结构，且 self-attention、text cross-attention、audio condition 的容错不同。可迁移的是动态预算思想，而不是原有 head 分类和索引器参数。

### Q2：如果迁移到视频模型，最安全的切入点是什么？

先只处理高分辨率视频 self-attention，并让 text/audio cross-attention 保持 dense；先验证固定密度，再考虑用累计质量阈值动态改变保留率。低分辨率或短序列上的收益可能不足以覆盖索引开销。

## 局限与疑问

- 需要额外训练索引器和校准稀疏路径，不是完全 training-free。
- 论文的速度数字依赖长上下文、硬件和 kernel；较短序列未必有净收益。
- 对视频生成的空间邻域、时间连续性及多模态条件并无直接保证。

## 我的判断

最有价值的是“让稀疏率服从当前 query 的相关性分布”。若用于视频模型，应把它视为 PISA 一类结构化稀疏之后的第二阶段优化，而不是第一版实现。

## 下次只看这些

1. 低维索引器负责找 token，动态 top-p 负责决定找多少。
2. 只动 retrieval-heavy attention，条件分支先保持 dense。
3. 视频迁移先证明质量与 kernel 净收益，再训练动态控制器。
