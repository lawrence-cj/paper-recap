## 研究问题

同一组 Transformer 层反复执行，可以增加每个 token 的计算深度而不复制主体权重。但简单循环未必持续改善效果：上一轮的信息只通过最终状态传递，或者后面的计算直接绕过中间轮次。

LoopRes 将 Kimi 团队的 Attention Residuals（AttnRes）用于循环模型，再针对循环状态相似、可读取来源不断增长的问题修改读取规则。论文验证对象是 Qwen 和 Llama 等模型，没有验证把某个现成 Kimi 模型直接改成循环模型。

## 核心方法

### 共享主体权重，增加有效深度

把模型切成 Prelude、Core、Coda：前后两段各运行一次，中间 Core 运行 $L$ 次。Qwen3-1.7B 的 28 层切为 7 / 14 / 7；$L=3$ 时，每个 token 经过 $7+14\times3+7=56$ 次层计算，约为原模型的两倍。Core 再分为两个连续 block。

### 用两种信息选择残差来源

AttnRes 分别保存 block 输出，让每个 Attention、MLP 子层学习读取哪些来源。LoopRes 在内容打分之外，给来源增加轮次和 block 身份：

$$
z_s=q_c^\top\operatorname{RMSNorm}(v_s)+q_\ell^\top k_s^{\mathrm{loop}},\qquad
\alpha_s=\operatorname{softmax}_{s\in\mathcal S}(z_s),\qquad
x=\sum_{s\in\mathcal S}\alpha_s v_s.
$$

$v_s$ 是来源状态；$q_c$、$q_\ell$ 是当前子层在当前轮的可训练 query；$k_s^{\mathrm{loop}}$ 是来源对应的可训练身份向量。内容项随输入 token 改变，身份项提供对轮次和 block 的偏好。Query 不是由当前 token 线性投影得到的普通 self-attention query。

两个 query 初始化为零，读取从均匀权重开始；身份 key 用标准正态分布初始化。主体 Attention、MLP 权重跨轮共享，小型读取 query 按轮设置。

若来源张量为 $[S,N,T,D]$，内容分数为 $[S,N,T]$，身份分数为 $[S]$ 并广播。沿来源维 $S$ 做 softmax，加权求和后恢复 $[N,T,D]$。这里选择的是不同深度和轮次的状态，普通 self-attention 仍然处理 token 之间的关系。

### 只读取有限的历史轮次

默认残差窗口 $W=1$：保留 Prelude 输出、上一轮各 block 输出、当前轮已完成的 block 输出，以及当前 block 内累积的 Attention/MLP 更新。更老的 block 输出移出可直接读取的集合。

窗口减少绕过中间轮次的捷径，并限制每次读取的来源数量。Prelude 始终保留，因此它不是强制每条路径都经过所有循环的数学保证。$W$ 限制的是残差历史轮次，不是 token 上下文长度。

训练使用最后一轮经 Coda 输出的 next-token 交叉熵，进行全参数微调。内部循环发生在 hidden states 上，模型仍会生成显式思维链。

## 关键发现

Qwen3-1.7B 在七项数学和代码基准上的平均分如下。计算倍率按每个 token 经过的层数衡量，不等于实际延迟倍率。

| 方法 | 相对层计算量 | 平均分 |
|---|---:|---:|
| 普通 SFT | 1× | 43.2 |
| Huginn 循环基线 | 2× | 49.0 |
| Huginn + AttnRes | 2× | 53.9 |
| 完整 LoopRes | 2× | 55.8 |
| 完整 LoopRes | 4× | 57.8 |

55.8 相对 43.2 提升 29.1%，对应增加 12.6 个分数点。相当一部分收益已经来自加入 AttnRes，循环专用修改在该基础上进一步提高效果。

论文表 5 的消融保留相同窗口，只改变读取打分：

| 读取方式 | 3 轮，2× 计算 | 7 轮，4× 计算 |
|---|---:|---:|
| 内容 + 轮次身份 key | 55.8 | 57.8 |
| 仅内容 key | 54.9 | 55.8 |
| 仅轮次身份 key | 54.9 | 57.5 |

身份 key 有收益，且在更多循环时更明显；但没有它，模型仍然有效。这里没有统计显著性证据，不能把分数差解释成普遍保证。

## 我的提问

### Q1：就是在 Qwen 上加 AttnRes，同时适配 loop？在 Kimi 上是否只需加 loop？

这个概括基本正确，但需附加条件：如果目标模型本身已有 AttnRes，仍需设计循环位置、加入轮次身份信息、限制残差来源窗口，并重新微调。不能把 Kimi 所有模型都默认视为相同的 AttnRes 架构。本文没有提供现成 Kimi 模型上的迁移验证。

### Q2：轮次身份 key 是必要的吗？

不是让循环能运行的必要条件。仅内容 key 的消融依然有不错效果，完整设计在 3 / 7 轮分别领先 0.9 / 2.0 分。合理解释是，同一组权重多次产生的状态很相似，显式身份让读取规则不必仅靠内容分辨来源。

### Q3：只看当前轮，不读上一轮，会有很大区别吗？

必须先明确下一轮的初始状态来自哪里。

- 如果上一轮最终输出仍作为当前轮输入，只取消对上一轮各 block 输出的直接读取，就接近普通 stack-loop。历史信息仍然存在，但需要通过一个最终状态传递。这个对照改变了信息通路，不能用“去掉身份 key”的消融代替。
- 如果每轮都从同一个 Prelude 输出重新开始，且没有历史状态、轮次条件或其他跨轮变化，共享模块在相同输入下只会重复相同的确定性计算。
- 即使只读取当前轮来源，若当前轮已通过初始化接收上一轮状态，循环依赖仍然存在。判断是否真正移除历史，必须检查初始化和所有残差连接。

因此，“去掉身份”“取消直接读取旧 block”“取消所有跨轮状态传递”是三个不同实验。本文表 5 只直接回答第一个问题。

### Q4：这里的 key/value 与 self-attention KV cache 有什么关系？

残差读取的 value 是 block 状态，key 用于选择深度来源；self-attention 的 K/V 用于跨 token 读取，两者不能混淆。

官方实现按“层、轮次”分别缓存 self-attention KV：第 2 轮当前 token 读取第 2 轮历史 token 的 KV。它不需要把所有轮次的 KV 拼成额外 token 上下文，但也不能因权重共享而直接共用同一份 KV，因为各轮的输入状态不同。

### Q5：微调需要多少资源？

论文的 1.7B 实验使用约 57.2 万对话、3.1B token；全局 batch 16、打包序列长 16,384、12,000 步、BF16、AdamW、学习率 $3\times10^{-5}$。按配置计算输入量：

$$
N_{\mathrm{tokens}}=12000\times16\times16384=3{,}145{,}728{,}000.
$$

若实测集群总输入吞吐为 $R$ token/s，纯训练小时数约为 $N_{\mathrm{tokens}}/(3600R)$：20K / 50K / 100K token/s 分别对应 43.7 / 17.5 / 8.7 小时。这只是换算，不是特定 GPU 的吞吐承诺，也未包括评测、存盘和数据准备。

论文正文和附录未明确给出 GPU 型号、卡数和完整训练耗时，确切 GPU-hours 待补充。前面对话中提及的“1.7B 用 2–4 张 80GB、4B 用 4–8 张、8B 用 8 张起评估”仅是未经实测的预算假设，不是作者配置、最低需求或复现保证。应先测 16K、3 轮的显存和吞吐再定预算。

官方代码使用 FSDP2、梯度检查点和分块输出 loss。公开 YAML 的梯度累积为 4，全局 batch 随进程数改变；`max_steps: 12000` 是上限，实际还受数据打包和 epoch 数约束。不能直接套用任意卡数并假设训练量与论文相同。

论文的“额外耗时 4.8%”以相同循环次数的普通残差模型为参照，不是相对 1× 普通 SFT；8.62GiB 指激活显存，不是训练总显存。大型 MoE 的权重、优化器显存要看总参数量，不能仅看每 token 激活参数量。

## 局限与疑问

- 不同循环深度分别训练；不能据此保证同一个 checkpoint 推理时任意加圈都能改善。
- 每个 token 仍执行全部预设循环。来源权重随 token 改变，不等于实现了动态提前退出或实际跳过计算。
- 取消跨轮 block 直接读取、仅保留最终状态传递后，效果下降多少，不能从身份 key 消融中推出。
- 评测重点是数学和代码，不能直接外推到通用对话、所有模型架构或视频生成。
- 总训练成本、GPU-hours 和大型 Kimi 模型上的可行性仍需验证。

## 我的判断

我的关注点是：是否必须显式区分每一轮，以及能否通过只传递上一轮最终状态来简化。现有消融支持身份信息有用，尤其在较多循环时；还不足以证明复杂的跨轮读取在所有设置下都必要。

阅读后的工作判断：这篇的价值在于把跨层状态读取用于预训练模型循环，并解决重复状态的选择问题。复现时值得固定数据和计算预算，分别对照普通循环、循环 + AttnRes、完整 LoopRes，以及只传最终状态的简化方案；后者属于待验证实验，并非本文已证实的等价替代。
