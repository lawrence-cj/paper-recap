## 研究问题

主要任务是让 AI 玩陌生小游戏：起初不给游戏规则和通关目标，只给当前画面和可用操作；模型需要尝试操作、观察变化、推断规则，最终通关。它研究视觉交互与推理，和图像、视频生成没有直接关系。

能看懂一张图片，不等于能连续玩好一个游戏。模型第一次看图时，可能不知道哪个细节以后会有用；对话变长后，旧图退出上下文，文字总结也可能遗漏证据。后续需要核实时，模型未必还能看到当时的原图。

阅读依据：[论文 v1](https://arxiv.org/html/2610.02200v1)、[作者介绍与游戏回放](https://vista-research.github.io/)、[官方代码](https://github.com/joshhhhhan/VISTA)。arXiv 版本提交于 2026-10-01，作者介绍是更早的版本；下面的实验数字统一采用论文 v1。

## 核心方法

![VISTA 的视觉输入、原始画面记忆、主动查看工具与观察—推理—行动流程](media/vista/method-overview.webp "论文 Figure 3：每一步观察、推理、行动，模型可按需查阅旧图与笔记。来源：Han et al., VISTA，arXiv:2610.02200v1 Figure 3，https://arxiv.org/html/2610.02200v1#S3.F3；CC BY 4.0；原图无损转为 WebP，未改动图内内容。")

- **直接使用已有多模态模型。** GPT-5.6 Sol、Claude Opus 5.0 本来就能看图。VISTA 没有训练一个新视觉模型，也没有给纯文本模型新增视觉编码器。
- **保存原始视觉记录。** 环境返回的所有画面，包括动作中的动画帧，按回合和帧编号保存，独立于当前对话上下文。这里的“无损”指截图被完整保存，不代表模型的理解没有误差。
- **让模型主动查图。** `inspect` 调出旧帧、比较多个画面或放大局部；`read_pixels` 读取精确像素值。模型根据当前疑问选择需要的视觉证据。
- **执行操作并保留笔记。** `play` 执行游戏动作；`history` 查看操作历史。`GUIDE.md` 记游戏规则，`WORKING.md` 记当前状态和计划，对话压缩后这些资料仍可用。

| 谁 | 收到什么 | 产出什么 |
| --- | --- | --- |
| 多模态模型 | 当前截图，以及按需调出的旧图、工具结果和笔记 | 文字分析、操作指令或查看历史的请求 |
| VISTA | 模型的工具请求 | 执行操作、调出截图或返回像素值 |
| 游戏程序 | 点击、移动等动作 | 更新后的游戏画面，以及进度或通关状态 |

流程是：看截图 → 决定操作 → VISTA 执行 → 游戏返回新画面 → 模型检查变化 → 继续。新的画面来自游戏程序，模型主要生成文字与工具调用。

## 关键发现

以下结果来自 [论文 §4](https://arxiv.org/html/2610.02200v1#S4)。RHAE 衡量通关情况和相对首次游玩人类的动作效率，不是图像质量分数。

- **公开游戏上的结果。** Opus 5.0 完成全部 25 个公开 ARC-AGI-3 游戏，RHAE 为 100.00；使用 7,302 个游戏动作，人工参考为 17,135 个，减少 57.4%。GPT-5.6 Sol 得分 99.00。
- **更直接的证据是消融。** 同一个 GPT-5.6 Sol、同一 CLI 接口下逐步加入组件：

| 配置 | RHAE |
| --- | ---: |
| 已有连续对话和文字笔记 | 70.05 |
| 加入原图记忆与主动查看 | 94.10 |
| 再加入精确像素读取 | 99.00 |

原图记忆与主动查看的组合带来明显提升；这组实验没有分别隔离“保存原图”和“查看工具”的独立贡献。

## 我的提问

### Q1：这里的任务究竟是什么？

让模型自己探索小游戏并通关。模型会根据操作前后的画面推断对象作用、移动规律和可能的目标；游戏程序负责判断有没有完成任务。它不是接收文本后生成一段游戏视频。

### Q2：所谓视觉模型会生成什么？

它是能看图的语言模型，主要输出文字和指令，例如“向右移动一次”“点击某个位置”“把第 3 步截图给我看”。VISTA 执行指令，游戏运行后产生下一张截图，再交给同一个模型。

### Q3：保存的历史图片具体怎么用？

下面是本次讨论的简化例子，不是论文中的实际游戏：蓝块踩到绿色开关后，红色门打开。若模型后来不确定开门原因，可以要求查看踩开关前后的两张截图。

VISTA 根据编号找到旧图，按要求裁剪或放大，再把图片作为新的视觉输入交给模型。模型比较两张图，核对自己的判断，然后继续操作。历史在这里是可重新检查的证据，不是训练新模型的数据，也不必每次把全部旧图放进上下文。

### Q4：所以它与视觉生成无关，实际还是调用现成大模型？

是。需要修正的是“Harness 给语言模型加入看图能力”这一理解：看图能力原本就属于所调用的多模态模型。Harness 提供的是保存、查阅和操作工具，改善模型利用视觉信息的方式。

### Q5：如果方法就是保存截图、调工具，论文真正想表达什么？

作者想说明：任务表现同时受模型能力和外部运行程序影响。让已有模型能按需回看原始证据，可以明显改善连续交互中的表现。

本次讨论的判断是，方法实现确实简洁，贡献主要在系统设计与实验验证。关键不只是“截图存下来了”，而是模型能在产生新疑问时选择旧画面、重新查看，并据此调整下一步操作。

## 局限与疑问

- **公开测试与训练数据可能重合。** 作者无法排除公开游戏进入模型训练数据；私有新游戏才是更强的泛化检验。
- **官方基线不是完全受控的对照。** 官方 API 与作者 CLI 接口、运行预算不同，Opus 的推理强度也不同。应优先看同一接口下的逐步消融。
- **动作少不等于计算省。** 查看历史和内部推理不计入游戏动作数；论文默认 GPT 配置报告平均每个游戏约 3,070 万 token 用量。
- **保存无损不保证理解正确。** 图像细节仍可能被误读，模型也可能没有选择真正需要检查的帧。

以上设置与限制见 [论文附录 A](https://arxiv.org/html/2610.02200v1#A1)和 [§6](https://arxiv.org/html/2610.02200v1#S6)。公开游戏成绩不能直接证明它能处理任意真实环境。

## 我的判断

本次讨论最终将它定位为视觉 Agent 的系统设计与实验论文。已有多模态模型负责看图、推理和决定动作，VISTA 负责让证据可查、操作可执行。它没有提出新的图像或视频生成算法。

值得记住的是：评测得到的是整个系统的表现；成绩差时，也需要检查模型拿到了什么信息、历史如何保留、能否回头核对。对视频理解的启发是保留原始帧并按问题重新查看，但这不是论文已经验证的视频生成收益。
