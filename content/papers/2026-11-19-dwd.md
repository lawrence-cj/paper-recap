## 研究问题

Latent diffusion 需要在多步去噪之后，用独立 VAE decoder 将 latent 解码成像素。少步视频生成中，这部分固定耗时占比尤其明显。原生 pixel diffusion 虽然没有 decoder，却也容易缺少细腻纹理。

DWD 将“决定采样方向”和“生成最终清晰像素”交给两个输出头，复用 DiT 已有的计算。本文依据 [2026-11-18 的论文 v2](https://arxiv.org/html/2611.22287v2)及[项目页](https://hanshengchen.com/dwd/)整理；结果为作者报告，未独立复现。

## 核心方法

### 保留 latent 采样，最后一步直接输出像素

- 原路径：带噪 latent → DiT → denoising head → 更新 latent；采样结束后再经 decoder 输出像素。
- DWD：保留原 denoising head，在同一组最后层特征上增加 pixel head。中间步骤继续更新 latent，最后一次 DiT 前向改由 pixel head 直接预测干净像素。
- 线性探针显示，最后层 token 比去噪后的 latent 更容易线性重建像素；DWD 读取的是高维隐藏特征，不是把最终 latent 直接线性放大。
- 最后输出发生在非零时间步；直接在完全干净的状态上调用 DWD，质量会下降。最后一步仅运行 conditional 分支，不再做 CFG 双分支求值。
- 只微调最后若干 transformer blocks、两个 head 和相关 modulation。共享 timestep embedding MLP 复制一份供适配尾部使用，前缀保持冻结。

可直接查看[论文 Figure 2 方法图](https://arxiv.org/html/2611.22287v2#S3.F2)。已检查项目页的方法图与论文许可；论文使用 arXiv non-exclusive distribution license，未确认项目页图片另有开放转载授权，因此本站只链接原图，不复制媒体。代码仓库的 Apache-2.0 许可不自动覆盖项目页图片。

### 一个 token 如何生成像素块

设最后层第 $i$ 个视觉 token 为 $h_i\in\mathbb R^D$。若它对应一个 $P\times P$ 彩色像素块，则 pixel head 为：

$$
p_i=W_{\rm pix}h_i+b_{\rm pix},\qquad
W_{\rm pix}\in\mathbb R^{(3P^2)\times D}.
$$

以 $D=4096$、$P=16$ 为说明性例子，一个 token 经过 Linear(4096, 768)，输出 $16\times16\times3=768$ 个颜色值，再 reshape 成像素块。4096 是示例隐藏维度，不是所有模型的配置。所有 token 共用同一个线性层。

对 $256\times256$ 图片，token 网格为 $16\times16$，共 256 个 token。省略 batch 维度，张量变化为：

```text
[256, D] → Linear(D, 768) → [256, 768]
         → reshape → [16, 16, 16, 16, 3]
         → permute(0, 2, 1, 3, 4) → reshape → [256, 256, 3]
```

中间五个维度依次为“块行、块列、块内行、块内列、颜色”。位置由 token 网格固定决定；线性层预测数值，reshape/permute 负责按空间位置拼接。拼块操作本身没有可训练参数。每个 token 此前已通过 attention 融合其他位置的信息，因此各块并非彼此独立生成。

论文的 latent 模型输出 normalized Oklab 三通道值，再转成 RGB 计算像素损失；ImageNet pixel 模型直接输出 RGB。Wan 一般 token 输出 $4\times16\times16\times3=3072$ 个值，覆盖四帧的局部块；第一 latent 帧使用独立的 $1\times16\times16$ 输出头。

### 两个 head 的 loss

真实图片或视频为 $x$，条件为 $c$，用原 encoder 得到 $z_0=E(x)$。采样高斯噪声 $\epsilon$，构造：

$$
z_t=(1-t)z_0+t\epsilon.
$$

**像素支路**在小噪声时间 $t_{\rm pix}$ 上前向，得到特征 $h_\theta=F_\theta(z_t,t_{\rm pix},c)$，经 pixel head、拼块及必要的颜色转换得到 RGB 预测 $\hat x$：

$$
\mathcal L_{\rm pix}
=\mathbb E\left[
\|\hat x-x\|_1
+\operatorname{LPIPS}(\hat x,x)
+\alpha\ell_{\rm adv}(\hat x)
\right].
$$

- L1 比较对应位置的颜色数值，约束基本结构和颜色。
- LPIPS 用固定感知网络比较特征，约束视觉结构与纹理。
- 对抗项通过判别器鼓励真实感；判别器另用真实与生成样本训练。L1 与 LPIPS 权重为 $1:1$，$\alpha$ 通过预测像素处的梯度范数自适应平衡；生成器对抗项只在后期启用。
- LPIPS 与判别器看的是图像或裁块，不是直接比较 token 向量。文生图和视频判别器使用随机 $256\times256$ 裁块；视频判别器还在逐帧特征上加入时间维卷积。

**去噪支路**另采 $t_{\rm traj}$，把相同的带噪输入、时间和条件分别交给微调模型与冻结原模型。以 $u_\theta$ 和 $u_{\rm ref}$ 表示两者预测的 latent 速度：

$$
\mathcal L_{\rm traj}
=\mathbb E\left[
\left\|u_\theta(z_t,t_{\rm traj},c)
-\operatorname{stopgrad}\big(u_{\rm ref}(z_t,t_{\rm traj},c)\big)\right\|_2^2
\right].
$$

这里的监督是原模型预测，不是重新对真实 flow 速度 $\epsilon-z_0$ 做普通预训练。所谓保持 trajectory，是在带噪真实数据上匹配预测，不能理解成整条生成轨迹严格不变。

$$
\mathcal L=\mathcal L_{\rm pix}+\lambda\mathcal L_{\rm traj}.
$$

| 参数 | 像素 loss 更新 | 轨迹 loss 更新 |
| --- | --- | --- |
| 新 pixel head | 是 | 否 |
| 原 denoising head | 否 | 是 |
| 共用的可训练 DiT 尾部 | 是 | 是 |
| 冻结前缀与参考模型 | 否 | 否 |

两个 loss 的时间分别采样，通常使用 shift 前的 $t_{\rm pix}\sim U[0,0.1]$ 与 $t_{\rm traj}\sim U[0.04,1]$；Wan 和少步模型有专门调整。分别反向传播、累积梯度，再更新一次。参考模型与学生可以共用冻结前缀的前向计算，但像素支路与轨迹支路因时间不同，不能视为总共只做一次前向。标准训练直接由真实数据加噪构造输入，无须每次跑完整采样轨迹。

## 关键发现

| 模型与指标 | 原模型 | DWD | 含义 |
| --- | --- | --- | --- |
| REPA-E，ImageNet FID ↓ | 1.12 | 1.06 | 去掉 decoder 后仍可改善质量 |
| AnisoFlow-H/16，ImageNet FID ↓ | 1.55 | 1.43 | 原生 pixel diffusion 也受益 |
| AnisoFlow-H/16，合并两个 head 的消融 FID ↓ | 1.55 | 1.71 | 相同像素损失直接施加给共享 head 会退化 |
| FLUX.2 klein Base，COCO FID ↓ | 15.13 | 15.05 | 基本保持原质量 |
| FLUX.2 klein 四步版，COCO FID ↓ | 21.50 | 21.92 | 并非所有单项指标都改善 |
| Wan2.1 14B，warping error × $10^{-3}$ ↓ | 1.52 | 1.18 | 约降低 23% |

Wan 同数据、同像素损失下只微调原 decoder，warping error 为 1.39，改善小于 DWD。但 DWD 的 dynamic degree 从 0.736 降至 0.711，imaging quality 也略降；不能将光流误差改善解释为所有视频能力全面提高。

论文附录 B.3 的四步模型端到端耗时：FLUX 从 0.776 秒到 0.695 秒，约加速 $1.12\times$；Wan 1.3B 从 4.661 秒到 2.757 秒，约加速 $1.69\times$。测量为 eager mode，没有 torch.compile。最后一步 FLOPs 的节省不能直接当成整段生成的加速倍数。

## 我的提问

### Q1：两个 head 分别对谁计算 loss？

新 pixel head 对真实图片或视频计算 L1、LPIPS 和对抗损失；原 denoising head 对冻结原模型的速度输出计算 L2。两者共用的可训练尾部同时接收两项梯度。输出目标分开，不代表共享特征完全解耦。

### Q2：每个 token 怎么恢复成 pixel？

线性层将 $D$ 维特征映射成 $P\times P\times3$ 个颜色值，再 reshape 成块，按 token 网格拼成图片。生成颜色需要训练，重新排列不需要。Wan 再把输出维度扩展到时间轴；H3 的输出块更大，需要轻量 refiner。

### Q3：所以本质上是微调或蒸馏一个训练好的模型？

是。标准 DWD 是“像素有监督微调 + 参考模型输出蒸馏约束”：已有模型提供生成能力，适配尾部和新 head 学习直接输出像素。H3 的特殊版本采用 decoder distillation，像素目标改为参考模型完成原生最后一步、再经原 decoder 得到的输出。DWD 本身不负责将采样步数变成两步，少步蒸馏是另一部分。

### Q4：训练成本多大，需要多少数据、训多久？

下表来自附录 A.2。GPU 小时是作者估算的 H100 计算成本，不包含原模型预训练；八卡时间只按 GPU 小时除以 8 换算，假设相同效率，并非作者报告的实际八卡耗时。

| 模型 | 微调 blocks | 步数 | H100 GPU 小时 | 八卡等效时间 |
| --- | --- | --- | --- | --- |
| JiT / AnisoFlow，ImageNet | 2/32 | 4k | 8 | 约 1 小时 |
| AnisoFlow 文生图 | 4/23 | 3k | 14 | 约 1.8 小时 |
| FLUX.2 klein Base 9B | 4/32 | 26k | 350 | 约 44 小时 |
| FLUX.2 klein 9B，四步版 | 4/32 | 26k | 340 | 约 43 小时 |
| Wan2.1 1.3B，四步版 | 8/30 | 40k | 980 | 约 5.1 天 |
| Wan2.1 14B | 8/40 | 40k | 4300 | 约 22.4 天 |

- **独立数据量与读取次数要分开。** ImageNet 模型使用 ImageNet 训练集；两种 pixel ImageNet 模型的 $4000\times1024$ 约为 410 万次读取，包含重复采样。
- **文生图**用 TextAtlas、RedCaps、LAION-Aesthetics 混合数据，论文未明确给出最终独立图片总数。AnisoFlow 为 $3000\times128=38.4$ 万次读取；四步 FLUX 为 $26000\times128=332.8$ 万次读取。Base FLUX 混合分辨率与 batch，不能直接套用 batch 128。
- **视频**用 Vchitect T2V DataVerse，最终独立视频数量待补充。按分辨率与时长分桶：352×640 使用 33/81 帧，480×832 使用 25/49/81 帧，720×1280 使用 17/33 帧，各桶 batch 不同。只取源分辨率至少 720p 的视频再下采样，作者认为这对清晰监督很重要。
- **1 万张图只用于初始化线性 head**，后面还要继续微调，不能当成总训练数据需求或最低数据门槛。
- 尽管只对尾部反向传播，完整 DiT 前向、参考尾部、感知网络和判别器仍有成本，视频版本不算廉价。论文未证明上述步数或数据是最低需求。

### Q5：H3 是否也能只加一个线性层？

论文附录 B.5 指出，H3 每个 token 最多对应 $4\times32\times32\times3=12288$ 个像素值，大于隐藏维度 5376 的两倍。纯线性输出能力有限，需要轻量 refiner；其文本、视觉和音频 token 还共享 transformer 权重。作者尚未确定最佳 refiner 架构，H3 的数据量、训练步数和 GPU 小时均待补充，不能直接照搬 Wan 的预算。

本条补充了此前 [pi-H3 博客笔记](https://junsongc.top/paper-recap/#paper=pi-h3)中尚未披露的 DWD 训练细节；旧笔记记录的是当时博客的信息，不能把这里的 DWD 细节扩展理解为 pi-Flow v2 两步算法也已完整公开。

## 局限与疑问

- 双 head 的梯度仍在共享尾部相遇，trajectory anchoring 是软约束，不是同 seed 结果严格不变的保证。
- 两个 head 的消融有力支持分开监督；将退化归因于多样性损失则是作者解释，不能仅凭 FID 完全确定因果。
- 部分视频指标与四步 FLUX FID 略退化；warping error 必须结合运动幅度、细节和整体质量评估。
- H3 只是初步结果，refiner 尚未定型，也没有相应成本表。项目页当前仍将代码标为 coming soon，发布状态可能变化。
- 精确数据子集规模、最低数据需求，以及迁移到其他模型后的质量与预算，均待补充。

## 我的判断

用户确认的理解：这是在训练好的模型上做微调或蒸馏，重点关心两个 head 的监督、token 如何输出像素，以及训练代价；尚未决定复现。

Agent 的判断：最有价值的是复用 DiT 隐藏特征，将最终像素质量与采样输出分开优化。对少步视频，值得评估省掉 decoder 后的端到端收益；但完整后训练仍需要高质量像素数据，Wan 14B 的预算已到数千 H100 GPU 小时。H3 版本需要另行核实 refiner、监督构造与成本，不能据宣传延迟推断它容易复现。

## 下次只看这些

1. 原 head 对冻结原模型的速度做 L2；新 head 对像素做 L1 + LPIPS + 对抗损失；共用尾部同时受两项约束。
2. token → 线性层输出一整块颜色值 → reshape/permute 拼图；最后在非零时间步直接输出，H3 需要额外 refiner。
3. 图像 latent 适配约 340–350 H100 GPU 小时，Wan 14B 约 4300；独立数据规模和 H3 训练预算仍待补充。
