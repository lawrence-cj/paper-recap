## 研究问题

视频 Diffusion Transformer 的 Token 很长，Attention 很快成为推理瓶颈。已有训练后稀疏 Attention 通常分成两个阶段：先物化完整 Proxy Score Map 并用 Top-$k$/Top-$p$ 选块，再启动 Block-sparse Attention Kernel。这有三个问题：

- **路由本身不便宜**：完整 Proxy Map 和 Routing Indices 要写回、读出 HBM。
- **预算不理想**：Top-$k$ 对每个 Query Block 固定相同预算；Top-$p$ 虽是动态预算，但不同 Query 的 Block 数可能严重失衡。
- **Keep-or-drop 太激进**：未选中的 Block 被完全清零；稀疏率越高，许多小贡献累积起来越不可忽略。

Sol-Attn 的目标不是只设计一个更好的 Mask，而是把 **Dynamic Routing、Sparse Exact Attention 和 Dropped-tail Approximation** 融合成一个 Nested Online-softmax Operator，避免单独物化 Mask。

## 核心方法

### 先记住一句人话

把每个 Key Block 想成一个文件夹：

- 外循环先看每个文件夹的“封面” $\overline K_j$，便宜地判断值不值得打开。
- 值得打开的文件夹进入内循环，读取原始 $K_j,V_j$ 做 Exact Attention。
- 不值得打开的文件夹也不直接扔掉，而是用“平均 Key + Value 总和”估算它的整体贡献。
- Exact 与 Approx 两条路径最后都写入同一份 Online-softmax Accumulator。

### 1. Block 与三个压缩量

将长度 $L$ 的序列分成 $N=L/B$ 个 Block，每个 Block 有 $B$ 个 Token：

$$
Q_i,K_j,V_j\in\mathbb{R}^{B\times d}.
$$

对 Query 和 Key 取 Token 维均值，对 Value 取 Token 维求和：

$$
\overline Q_i=\frac{1}{B}\sum_{r=1}^{B}q_{i,r},
\qquad
\overline K_j=\frac{1}{B}\sum_{u=1}^{B}k_{j,u},
\qquad
\widehat V_j=\sum_{u=1}^{B}v_{j,u}.
$$

这里最容易混淆的是：**$K$ 取均值，$V$ 却取求和。**原因不是经验选择，而是近似公式要求如此：$\overline K_j$ 代表 Block 中每个 Key；若把这个代表 Logit 重复 $B$ 次，分母自然乘 $B$，分子则乘以整个 Block 的 Value Sum。

### 2. Threshold 中的 Mean 不是当前 Chunk 的 Mean

Query Block $i$ 与 Key Block $j$ 的标量路由分数为：

$$
\widehat s_{ij}=\overline Q_i\overline K_j^\top.
$$

对固定 Query Block $i$，论文把它对全部 $N$ 个 Key Block 的 Proxy Score 看成一行：

$$
\widehat{\boldsymbol s}_i=
[\widehat s_{i1},\ldots,\widehat s_{iN}].
$$

这一整行的均值和标准差是 $\mu_i,\sigma_i$，Threshold 为：

$$
\tau_i=\mu_i+\beta\sigma_i,
\qquad
\mathcal S_i=\{j:\widehat s_{ij}>\tau_i\}.
$$

$\beta$ 是跨 Query 共享的 Standardized Cutoff；$\mu_i,\sigma_i$ 把它映射到当前 Query 的原始分数量纲。若 Proxy Score 近似高斯，平均选中密度约为：

$$
\rho_{\mathrm G}(\beta)=1-\Phi(\beta).
$$

一个看似循环的问题是：既然还没扫描全部 Proxy Score，如何预先得到它们的 Mean/Variance？答案是用 Pooled Keys 的全局矩：

$$
\mu_i=\overline Q_i
\left(\frac{1}{N}\sum_{j=1}^{N}\overline K_j\right)^\top,
$$

$$
\sigma_i^2=\overline Q_i
\left(\frac{1}{N}\sum_{j=1}^{N}\overline K_j^\top\overline K_j\right)
\overline Q_i^\top-\mu_i^2.
$$

因此 Pooled-Key 的一阶矩和二阶矩可以预先聚合；每个 Query Block 不需要先生成完整 $N$ 维 Proxy Row，便能得到自己的 $\tau_i$。

### 3. 四个“Mean/Sum”分别沿哪个轴

| 名称 | 沿哪个轴聚合 | 形状 | 用途 |
| --- | --- | --- | --- |
| $\overline K_j$ | Key Block 内的 $B$ 个 Token | $1\times d$ | 一个向量代表整个 Key Block |
| $\overline Q_i$ | Query Block 内的 $B$ 个 Token | $1\times d$ | 把一个 Query Block 压成路由 Query |
| $\mu_i$ | 固定 $i$，沿全部 $N$ 个 Key Blocks | Scalar | 决定 Query-dependent Threshold |
| $\widehat V_j$ | Value Block 内的 $B$ 个 Token 求和 | $1\times d$ | 保留 Approx Numerator 的总 Value 贡献 |

最重要的区分：$\overline Q_i$ 是在 **Query Token 轴**取均值，$\mu_i$ 是在 **Key Block 轴**对 Proxy Scores 取均值；它们不是同一个 Mean。

### 4. Outer Loop：Dense 扫描代表，不扫描原始 Key Tokens

外循环不一次处理全部 $N$ 个 Pooled Keys，而是每次加载 $C$ 个：

$$
\overline K^{(t)}
=[\overline K_{tC+1};\ldots;\overline K_{(t+1)C}]
\in\mathbb R^{C\times d}.
$$

关键是先计算一个 Token-to-block Tile：

$$
\widetilde S_i^{(t)}
=Q_i(\overline K^{(t)})^\top
\in\mathbb R^{B\times C}.
$$

它并不是最终 Exact Score。第 $c$ 列表示 $B$ 个 Query Tokens 分别与第 $c$ 个“平均 Key”相乘。对这列沿 Query Token 轴取均值：

$$
\operatorname{Mean}_{\mathrm{rows}}
\left(\widetilde S_i^{(t)}[:,c]\right)
=\overline Q_i\overline K_{tC+c}^\top
=\widehat s_{i,tC+c}.
$$

这解释了实现里的 `s_ij.mean(axis=0)`：

- 输入 $\widetilde S$ 是 $B\times C$。
- `axis=0` 消掉 $B$ 个 Query Tokens。
- 输出 $1\times C$，每个 Key Block 得到一个 Routing Scalar。
- 它只决定该 Key Block 是否进入 Inner Loop；Approximation 仍保留每个 Query Token 自己的 $B\times C$ 分数。

因此，**Routing 是 Block-to-block Scalar，Approximation 是 Token-to-block Vector。**不要把两者都想成一个标量。

### 5. Inner Loop：只对选中 Block 恢复 $B\times B$ Exact Attention

若某列满足 $\widehat s_{ij}>\tau_i$，外循环立即派发 $j$ 到内循环：

$$
S_{ij}^{\mathrm{exact}}=Q_iK_j^\top\in\mathbb R^{B\times B}.
$$

然后用原始 $V_j$ 更新精确分母与分子：

$$
D_{ij}^{\mathrm{exact}}
=\operatorname{RowSum}\left(\exp(S_{ij}^{\mathrm{exact}})\right),
$$

$$
N_{ij}^{\mathrm{exact}}
=\exp(S_{ij}^{\mathrm{exact}})V_j.
$$

所谓 Nested Loop，就是：

1. **Outer Loop** 依次扫描 Pooled-Key Chunks；每个 Chunk 都会走。
2. **Inner Loop** 只遍历当前 Chunk 中 Threshold 以上的 Key Blocks；数量动态变化。
3. 当前 Chunk 处理完后，回到 Outer Loop 扫描下一个 Chunk。

### 6. Approximation：未选中 Block 不是 Drop，而是把内部 Key 当成相同

对一个 Query Token $q$，把 Block $j$ 中每个 Key 写成：

$$
k_{j,u}=\overline K_j+(k_{j,u}-\overline K_j).
$$

令 $a=q\overline K_j^\top$、$\delta_u=q(k_{j,u}-\overline K_j)^\top$。因为 $\overline K_j$ 是均值，$\sum_u\delta_u=0$。在 $\overline K_j$ 处做 Taylor Expansion：

$$
\exp(a+\delta_u)
=\exp(a)\left(1+\delta_u+\mathcal O(\delta_u^2)\right).
$$

只保留零阶项，相当于假设 Block 内所有 Key 都等于 $\overline K_j$。于是 Exact Denominator：

$$
\sum_{u=1}^{B}\exp(qk_{j,u}^\top)
\quad\Longrightarrow\quad
B\exp(q\overline K_j^\top).
$$

Exact Numerator：

$$
\sum_{u=1}^{B}\exp(qk_{j,u}^\top)v_{j,u}
\quad\Longrightarrow\quad
\exp(q\overline K_j^\top)\widehat V_j.
$$

这就是为什么 Approx Branch 恰好需要 $\overline K_j$ 和 $\widehat V_j$：

$$
D_{ij}^{\mathrm{approx}}
=B\exp(Q_i\overline K_j^\top),
$$

$$
N_{ij}^{\mathrm{approx}}
=\exp(Q_i\overline K_j^\top)\widehat V_j.
$$

外循环已经算过 $Q_i\overline K_j^\top$，所以这份 Score Tile 同时承担三件事：**Routing、Approx Denominator、Approx Numerator**。这份复用是 Sol-Attn 真正漂亮的地方。

### 7. Exact 与 Approx 如何放进同一个 Online Softmax

对选中集合 $\mathcal S_i$ 和未选中集合 $\mathcal U_i$：

$$
D_i=
\sum_{j\in\mathcal U_i}D_{ij}^{\mathrm{approx}}
+\sum_{j\in\mathcal S_i}D_{ij}^{\mathrm{exact}},
$$

$$
N_i=
\sum_{j\in\mathcal U_i}N_{ij}^{\mathrm{approx}}
+\sum_{j\in\mathcal S_i}N_{ij}^{\mathrm{exact}},
\qquad
O_i=N_i\oslash D_i.
$$

Kernel 不会真的保存这些巨大指数矩阵，而是像 FlashAttention 一样维护 Running Max $m_i$、Running Denominator $\ell_i$ 和 Numerator Accumulator $\mathrm{acc}_i$。每来一个 Approx Column 或 Exact Tile，就按新的最大值重标度旧状态再合并。

被选中的列会在 Approx Branch 中 Mask 为 $-\infty$，再在 Inner Loop 走 Exact Branch，因此不会 Double Count。

### 8. 为什么 Outer Loop 仍然值得做

外循环仍会看全部 $N\times N$ 个 Block Pair，但每对只做 $B$ 个 Query 与一个 Pooled Key 的计算；内循环才做昂贵的 $B\times B$ Exact Score。粗略忽略常数：

$$
C_{\mathrm{outer}}\approx\frac{1}{B}L^2d,
\qquad
C_{\mathrm{inner}}\approx\rho L^2d,
$$

因此：

$$
C_{\mathrm{Sol}}\approx
\left(\rho+\frac{1}{B}\right)L^2d.
$$

这里 $\rho$ 是 Exact Block Density。Outer Loop 是“在 Block 数上 Dense”，但不是 Dense Token-to-token Attention。

## 关键发现

- 论文在视频生成与视频编辑上分别报告最高 $2.1\times$ 和 $2.3\times$ End-to-end Speedup，并保持接近 Dense Attention 的视觉质量；与 Sol-Engine 的互补优化结合时，视频生成最高达到 $5\times$ End-to-end Speedup。
- 在使用相同选中 Block Indices 时，Exact-or-Approx 始终比 Exact-only Sparse Attention 具有更低的相对 $\ell_2$ 误差和更高的 Cosine Similarity；稀疏率越高，Approximate Correction 的优势越明显。
- 相比只执行选中块的 cuDNN Block-sparse Attention，Sol-Attn 因额外做 Approx Correction，在 $10\%/15\%/20\%$ Exact Density 下分别增加 $9.4\%/3.9\%/1.6\%$ Kernel Latency；但把 Baseline 的独立 Routing 阶段算入 End-to-end 后，Sol-Attn 反而分别快 $6.2\%/6.2\%/6.6\%$。
- Thresholding 在保持 Query-dependent 动态预算的同时，让不同 Query 的密度比 Top-$p$ 更集中；$\beta$ 控制的是 Model-level Average Density，不保证每一行密度完全相同。

## 我的提问

### Q1：Outer Loop 和 Inner Loop 到底分别在循环什么？

固定一个 Query Block $Q_i$：Outer Loop 循环的是 **全部 Pooled-Key Chunks**；Inner Loop 循环的是 **当前 Chunk 内被选中的原始 $K_j,V_j$ Blocks**。Outer Loop 每次一定执行，Inner Loop 是否执行、执行几次由当前 Chunk 的 Threshold 结果决定。

### Q2：为什么实现先算 $Q_i\overline K^\top$，又对它取 Mean？直接算 $\overline Q_i\overline K^\top$ 不行吗？

若只为 Routing，直接计算 $\overline Q_i\overline K^\top$ 的确足够；但 Approx Correction 需要每个 Query Token 各自的 $q_{i,r}\overline K_j^\top$。Sol-Attn 先计算更丰富的 $B\times C$ Tile，再对列取均值得到 Routing Score。这样一份计算同时服务 Approximation 与 Routing，避免再算一遍独立 Proxy GEMM。

### Q3：为什么 $K$ 是 Mean，$V$ 是 Sum？

$\overline K_j$ 用来假设“Block 内 $B$ 个 Key 都等于同一个代表”；这个代表自然是均值。这个相同 Logit 在分母出现 $B$ 次，所以乘 $B$；分子中同一个权重分别乘 $B$ 个 Values，因此合并成 $\widehat V_j=\sum_u v_{j,u}$。若 $V$ 也取均值却不补乘 $B$，Approx Numerator 会少一个 Multiplicity Factor。

### Q4：Approximation 是给整个 Query Block 一个标量吗？

不是。Routing Score $\widehat s_{ij}$ 是一个 Block-to-block Scalar；Approximation Score $Q_i\overline K_j^\top$ 是 $B\times1$，每个 Query Token 都有自己的 Logit。它只是在 Key Token 维把一个 Block 压成了一个代表，没有把 Query Token 维也压掉。

### Q5：这种零阶近似什么时候准确？

当 Block 内 Key 对当前 Query 的投影很接近，即 $\delta_u=q(k_{j,u}-\overline K_j)^\top$ 较小时更准。由于 $\sum_u\delta_u=0$，Denominator 的一阶误差会抵消，主要从二阶开始；Numerator 还受 $\delta_u$ 与 $v_{j,u}$ 相关性的影响，所以通常更难近似。

### Q6：它和 BLASST 的边界是什么？

BLASST 先计算完整 Exact $QK^\top$，再根据 Exact Block Max 跳过 Softmax/PV，未选中块清零；Sol-Attn 在完整 Exact BMM1 之前用 Pooled Proxy 路由，未选中块保留零阶贡献。因此 BLASST 的判断更可靠但不能省去 Dense BMM1；Sol-Attn 能把 Exact $QK^\top$ 降到 $\rho L^2d$，代价是 Proxy 漏选和 Approximation Error。

### Q7：Sol-Attn 和 BLASST 能否结合？

可以。最自然的组合不是让两个方法并列运行，而是把 BLASST 放进 Sol-Attn 的 Exact Inner Loop，形成 **Early High-recall Proxy Routing + Late Exact-score Refinement + Approximate Fallback** 的三级路径：

$$
\operatorname{Path}(i,j)=
\begin{cases}
\mathrm{Approx}, & \widehat s_{ij}\le\tau_i,\\
\mathrm{Approx\ fallback}, & \widehat s_{ij}>\tau_i\ \text{且}\ m_{ij}^{\mathrm{exact}}-m_i^{\mathrm{run}}<\log\lambda,\\
\mathrm{Exact}, & \text{otherwise}.
\end{cases}
$$

其中 $\widehat s_{ij}$ 是 Sol-Attn 的 Pooled Proxy，$m_{ij}^{\mathrm{exact}}$ 是计算 $Q_iK_j^\top$ 后得到的 Exact Tile Max，$m_i^{\mathrm{run}}$ 是共享 Online-softmax Running Max。第一层 Sol Gate 决定是否值得支付 Exact BMM1；第二层 BLASST Gate 在已经计算 Exact Scores 后，决定是否继续支付 Exact Softmax、完整 $V_j$ Load 和 PV。

| Sol Proxy 判断 | Exact 事实 | Hybrid 结果 |
| --- | --- | --- |
| 不重要 | 不重要 | 直接 Approx，判断正确 |
| 不重要 | 重要 | False Negative；BLASST 无法补救 |
| 重要 | 不重要 | Sol False Positive；BLASST 可二次过滤并回退 Approx |
| 重要 | 重要 | 执行 Exact Softmax/PV |

因此 BLASST 只能清理 Sol Candidate 中的 **False Positives**，不能恢复 Sol 已经拒绝的 **False Negatives**。它带来的也是增量收益：Candidate 的 Exact $QK^\top$ 已经支付，只能继续节省 Softmax、$V$ Load 和 PV。

实现顺序必须是：

1. Outer Loop 计算 $a_{ij}=Q_i\overline K_j^\top$ 和 $\widehat s_{ij}=\operatorname{Mean}(a_{ij})$。
2. 若 Sol Gate 拒绝，立即合并 Approx Contribution。
3. 若 Sol Gate 接受，先暂缓合并并保留 $a_{ij}$，再计算 Exact $Q_iK_j^\top$。
4. 用 BLASST Gate 在 Exact 与 Approx Fallback 中二选一，最后才更新共享的 $m_i,\ell_i,\mathrm{acc}_i$。

不能先把 Candidate 的 Approx Contribution 写进 Online-softmax，再尝试换成 Exact，因为 Online-softmax State 不适合回滚或相减；同一个 Block 必须严格只走一条最终路径，否则会 Double Count。

两个 Threshold 也不应分别按目标 Density 独立校准。更合理的是让 Sol 的 $\beta$ 优先保证 Candidate Recall，再用 BLASST 的 $\lambda$ 提高 Candidate Precision。是否值得实现主要取决于 Sol-selected Blocks 中被 Late Gate 拒绝的比例 $r_{\mathrm{late}}$：若它很低，新增分支、寄存器生命周期和 Warp Divergence 可能抵消节省；若为了质量而把 Sol Candidate Density 设得较高，Late Gate 才更有价值。

## 局限与疑问

- 一个 Block 是否进入 Inner Loop 由 $B$ 个 Query Tokens 的平均表现决定；若某个 Block 只对少量 Query Tokens 极重要，列均值可能把它稀释。Approx Branch 能保留低阶贡献，但不能恢复该 Block 内的尖峰结构。
- 高斯假设只用于把 $\beta$ 映射成可预测的平均密度；真实分布偏斜、Heavy-tail 或带 Attention Sink 时，Per-row Density 仍会偏离 $1-\Phi(\beta)$。
- 当前方法面向 Bidirectional Visual DiT。迁移到 Causal/Autoregressive Attention 时，边界 Block 的有效 Key 数不是固定 $B$，Approx Denominator 的 Multiplicity 和 Pooled Statistics 都需要 Mask-aware 修正。
- Outer Loop 仍有 $L^2d/B$ 量级成本，并需要读取 Pooled $K$ 与 Summed $V$；当 Exact Density 很低后，这部分会成为新的性能下限。
- 零阶近似隐含 Block 内平滑性。若 Block 内 Key 高度异质或 Score Deviation 与 Value 强相关，Numerator Error 可能明显大于 Denominator Error。
- 与 BLASST 组合并非 Plug-and-play：Late Gate 的 Running Max 会受到 Approx/Exact 处理顺序影响，且保留 Candidate 的 $a_{ij}$ 会增加 Register 或 Shared-memory 压力。它不能修复 Early Proxy False Negative。

## 我的判断

Sol-Attn 最值得学习的不是单独的 Threshold 公式，而是 **一块数据做三份工作**：$Q_i\overline K^\top$ 同时提供 Routing Signal、Approx Denominator 和 Approx Numerator 的权重；Routing 因而不再是 Attention Kernel 前面的独立流水阶段。

它的系统设计可以概括为：用便宜 Outer Loop 给所有 Block 一个低保真通道，再给少数重要 Block 升级为昂贵 Exact Inner Loop，并让两条通道共享 Online-softmax State。这比 Keep-or-drop 更适合高稀疏率，也清楚地解释了它为何能突破只跳过 PV 的方法上限。

最值得继续验证的是 Block 内异质性：按 Query Token 分析 False-negative Blocks，观察它们的 $\max_r q_r\overline K_j^\top$ 与 $\operatorname{mean}_r q_r\overline K_j^\top$ 差异，能直接判断 Mean-based Routing 是否在尖峰模式上留下系统性盲点。

若要结合 BLASST，推荐把它定义成 Sol-Attn Candidate 的 **Exact Refinement Gate**，并让被它拒绝的 Candidate 回退到 Approx，而不是直接清零。实验上应联合扫描 $(\beta,\lambda)$，至少记录 Sol Candidate Density、Late-rejection Rate、Kernel Occupancy、端到端延迟和生成质量；只有 $r_{\mathrm{late}}$ 足以覆盖分支与状态保存开销时，这个 Hybrid 才成立。

## 下次只看这些

1. Outer Loop 算 $Q_i\overline K^\top$：列均值做 Routing，原 Tile 做 Approximation；Inner Loop 只对选中 Block 算 $Q_iK_j^\top$。
2. $K$ 取 Mean 是为了代表 Block，$V$ 取 Sum 是为了保留 $B$ 个 Token 的总贡献；Approx 分母因此还有一个 $B$。
3. 若结合 BLASST：Sol Gate 保证 Early Recall，BLASST Gate 提高 Late Precision；被二次拒绝的 Candidate 回退 Approx，并且只有 Late-rejection Rate 足够高时才值得。
