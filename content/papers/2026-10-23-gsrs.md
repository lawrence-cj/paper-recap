## 研究问题

视频 DiT 的长序列 attention 开销很大。块稀疏 attention 可以跳过部分 QK 和 PV 计算，但仍需决定每一步保留多少块，以及如何低成本地找到重要块。

GSRS 是无需重新训练的推理方法。作者在 HunyuanVideo 和 Wan 2.1 上观察到：去噪过程中 attention 通常越来越集中，早期选出的候选集合在后续步骤仍能覆盖较多注意力权重。它据此减少后期计算，并复用早期搜索范围。这里的观察是实验依据，不是对每个输入、每一步的保证。[原文 §4–5](https://arxiv.org/html/2610.21129v1#S4)

## 核心方法

原文 [Figure 4 方法图](https://arxiv.org/html/2610.21129v1#S5.F4) 可对照阅读。论文页面标注 arXiv perpetual non-exclusive license，未查到明确允许第三方转载原图的许可，因此这里使用原创示意图。

- **逐步增加稀疏度。** 对每个 head、每个 query block，按 key block 重要性排序，累计权重达到 Top-p 阈值就停止保留。默认 50 步中前 20% 使用全量 attention，第 10、20、30、40 步搜索，阈值依次为 0.95、0.90、0.85、0.80。0.95 是累计权重阈值，不是保留 95% 的块；不同层、head 和 query block 可以留下不同数量的块。
- **缩小后续搜索范围。** 第一次全量搜索建立候选掩码 $\mathcal S_1$；之后每次都重新评估 $\mathcal S_1$ 内的所有块，而不是只评估上一次留下的 $\mathcal S_{k-1}$。因此暂时排除的候选块可以重新入选，最初不在 $\mathcal S_1$ 中的块无法恢复。非搜索步使用最新掩码，但仍用当前步的 Q、K、V 计算。
- **在 attention 计算中收集精确评分所需的统计量。** FlashAttention 逐块计算时，最终 softmax 分母尚未确定。GSRS 先记录每个 query 行与每个 key block 的 log-sum-exp，等当前次 attention 完成后再归一化，避免使用旧去噪步骤的 LSE 造成误差。搜索步同时产生当前 attention 输出和用于后续选块的统计量，不为评分另算一遍 QK。
- **实现辅助。** 使用 128-token 块和 Generalized Hilbert 曲线重排，让同一块内 token 更接近于紧凑的时空区域。这是沿用已有工作的辅助设计。搜索步用 TileLang 融合计算，其他步骤用块稀疏 CUDA kernel。

对固定 head 和 query block $u$，令 $\mathcal C_t(u)$ 是在去噪步骤 $t$ 为搜索步时评估的候选 key blocks，$\mathcal K(\mathcal C_t(u))$ 是其中的 key tokens。第一次搜索包含所有块，之后的搜索使用 $\mathcal S_1[u]$。$B$ 是 query block 大小，$d$ 是 head 维度：

$$
z_{ij}=\frac{q_i^\top k_j}{\sqrt d},\qquad
G_{iv}=\log\sum_{j\in v}\exp(z_{ij}).
$$

$G_{iv}$ 是 query 行 $i$ 对 key block $v$ 的块内 LSE。实际用最大值移位计算以保持数值稳定。所有候选算完后，得到当前行的归一化量：

$$
L_i=\log\sum_{j\in\mathcal K(\mathcal C_t(u))}\exp(z_{ij}),\qquad
W_{uv}=\frac{1}{B}\sum_{i\in u}\exp(G_{iv}-L_i).
$$

$W_{uv}$ 是 query block 对 key block 的平均概率质量，对候选块求和为 1。Top-p 保证的是这些 query 的平均累计质量，不是每个 query 各自都达到阈值。后续搜索的“精确”仅针对候选集合内重新归一化的分布；$p=0.8$ 不保证保留原全量 attention 的 80% 权重。[§5.3 与附录 A.2–A.5](https://arxiv.org/html/2610.21129v1#S5.SS3)

## 关键发现

实验使用 HunyuanVideo-T2V-13B 和 Wan 2.1-T2V-14B，720p、50 步与 VBench prompts。以下加速比均为同一 GPU 上相对全量 attention 的端到端速度；计算密度来自 A800 主表。[主表 1](https://arxiv.org/html/2610.21129v1#S5.T1)、[附录 G](https://arxiv.org/html/2610.21129v1#A7)

| 模型 | Attention 计算密度 | A800 加速 | H800 加速 | VBench-Q：GSRS / Full |
|---|---:|---:|---:|---:|
| HunyuanVideo | 25.06% | 1.68× | 2.21× | 84.01 / 83.98 |
| Wan 2.1 | 30.63% | 1.55× | 1.78× | 83.72 / 83.75 |

- A800 上 HunyuanVideo 的延迟从 3057 秒降到 1825 秒，Wan 从 3689 秒降到 2380 秒。VBench-Q 接近全量基线，说明测试集平均质量指标基本保持，不说明所有样本都无损。
- 在 HunyuanVideo 的固定消融子集上，去掉 Reduced Search 后延迟从 1825 秒变为 1990 秒，密度从 25.06% 增至 28.62%，VBench-Q 接近。这个比较同时改变搜索范围和实际计算密度，不能把全部差异归因于排序开销。
- 论文报告的 13.75× 是所定义的额外 attention 与搜索开销之和的降低倍数，不是端到端加速。[附录 A.7](https://arxiv.org/html/2610.21129v1#A1.SS7)

## 我的提问

### Q1：缩小搜索范围和精确计算块权重，是怎么一起用的？

前者决定评估哪些块，后者在这些块的正常 attention 计算中收集统计并恢复当前权重。搜索步用较大的候选集合计算当前输出，产生的新掩码交给后续非搜索步使用。下面的块名是流程示例，不是论文测量：

| 去噪步骤 | 实际计算的块 | 是否评估重要性 | 新掩码或用途 |
|---|---|---|---|
| 第 10 步 | 全部 A、B、C、D、E、F | 是 | 选出初始候选 $\mathcal S_1=\{A,B,C,D\}$ |
| 第 11–19 步 | A、B、C、D | 否 | 复用 $\mathcal S_1$ |
| 第 20 步 | 整个 $\mathcal S_1$：A、B、C、D | 是 | 选出 $\mathcal S_2=\{A,B\}$ |
| 第 21–29 步 | A、B | 否 | 复用 $\mathcal S_2$，跳过其他块 |
| 第 30 步 | 仍是整个 $\mathcal S_1$：A、B、C、D | 是 | 可以改选 $\mathcal S_3=\{A,C\}$ |

搜索步的输出已经来自对应候选集合，不会再用刚选出的新掩码重算一次当前步。第 30 步能让 C 回来，是因为搜索范围仍是 $\mathcal S_1$；E、F 则不会再进入评估。[算法 4](https://arxiv.org/html/2610.21129v1#A1.SS5)

### Q2：为了知道哪些块重要，不还是要把它们算一遍吗？

是。第一次搜索要算全部块，后续搜索要算全部初始候选。GSRS 把这次计算同时用于当前 attention 输出和重要性统计，避免为评分另做一遍 QK；再把选块结果复用多步，分摊搜索成本。不能把它理解成不计算某个块就能知道其准确权重。

例如候选 A、B、C、D 的当前权重为 70%、22%、5%、3%，Top-p 为 90% 时保留 A、B，累计 92%。第 20 步已经算过四个候选块，主要的节省发生在接下来的第 21–29 步。

### Q3：第 20 步 C 不重要，第 21 步就重要了，难道不可能吗？

完全可能。这是本轮讨论指出的核心风险：第 20 步选出的 AB，不保证在第 21–29 步一直合适。以下是说明复用风险的假设分布，不是论文中的实测轨迹：

| 步骤 | A | B | C | D |
|---|---:|---:|---:|---:|
| 第 20 步 | 70% | 22% | 5% | 3% |
| 第 21 步 | 35% | 10% | 50% | 5% |

第二行表示如果重新评估同一候选集合会看到的权重。算法第 21 步只算 AB，不会发现 C 已经重要；实际稀疏 attention 会在 AB 内重新归一化，因此其输出可能偏离候选集合上的 attention。第 30 步虽能重新选回 C，也不保证消除前面漏算造成的轨迹偏差。

要每步准确检查 C 是否变重要，就需重新评估它。每步评估整个 $\mathcal S_1$ 会减少只算 AB 的收益；更便宜的预测或抽查仍需要评估其漏检风险。这是算法分析与改进方向，不是论文已验证的新方案。

### Q4：既然评分精确，而且 attention 越来越集中，为什么仍然没有保证？

三个概念必须分开：当前搜索步的候选内评分精确；复用期间块排序稳定；候选集合始终覆盖重要块。第一个可以由公式成立，后两个依赖实际 attention 动态。

attention 更集中，只说明权重集中在较少位置，不代表这些位置不变。论文固定早期掩码的高 recall 实验支持早期候选集合通常有较好覆盖，不能直接证明每次进一步缩小的 AB 子集在整个复用区间都可靠。GSRS 接受掩码可能过时的风险以换取速度，没有逐步最优或无损保证。

## 局限与疑问

- **两类遗漏需要分开。** 初始 $\mathcal S_1$ 之外的块无法重新发现；$\mathcal S_1$ 内暂时被排除的块，要等到下一次搜索才有机会回来。
- **评分精确不等于输出无损。** 当前候选内归一化精确，不保证原全量概率覆盖，也不保证忽略的 V 加权贡献足够小。
- **收益依赖生成设置。** 论文主要验证两个视频 DiT 的 50 步生成；4–8 步蒸馏模型的搜索成本能否摊薄、重要块是否同样稳定，需要另测。
- **统计缓存并非零成本。** 块 LSE 避免保存完整 attention 矩阵，但仍需中间存储与后处理。论文示例的统计存储量约为 4.6 GB，不能把融合 kernel 的低延迟开销理解成没有内存成本。
- **原文存在表述不一致。** 附录 A.1、H 中关于 cached LSE 的描述与 §5.3、算法 2/4、附录 A.5 不一致；本笔记按完整公式与算法解释为使用当前 LSE、不跨去噪步缓存 LSE。Hunyuan PSNR 的正文与主表数字也不一致，本文未将其作为关键结论。

## 我的判断

本轮讨论最值得保留的判断是：准确计算当前候选块的重要性，不能推出下一步仍然应该选同一批块。论文的平均质量和速度结果支持一种有用的经验折中，但没有消除跨步复用带来的不确定性。

若后续复现，建议重点检查每个复用间隔中的 attention mass recall、重要块突然变化的样本，以及缩短搜索间隔后的质量与端到端延迟。上述检查是本轮提出的验证方向，不是已经完成的实验。

## 下次只看这些

2. 块 LSE 加当前行 LSE 恢复候选内精确权重；搜索步当前输出用候选集合，新掩码用于之后的步骤。
3. 记住 AB/C 反例：第 20 步选对，不保证第 21 步仍合适；后期更集中也不意味着重要块位置不变。
